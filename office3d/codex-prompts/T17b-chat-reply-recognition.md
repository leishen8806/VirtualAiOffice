## 真实验证的事实（会话任务 CMP-333，评论时间线，UTC）
```
03:53:58 user   【对话】你好，这是一次对话功能的联通测试……              （第 1 轮，我发的）
03:54:17 agent  【对话】我主要负责整理、更新并沉淀公司知识库……          （第 1 轮回复，正常，用时 19 秒）
03:54:43 user   【对话】谢谢。你觉得知识库里现在最缺哪一类内容？……请按约定在最后一行写「建议任务」。  （第 2 轮）
03:54:55 agent  已修复任务处置记录并标记完成；对话回复已留在评论中。      ← 同事的「运行摘要」评论，不是回答
03:55:06 agent  【对话】我目前不能在这次对话里检查仓库……                  ← 真正的回答
                建议任务：知识库内容缺口盘点 | 核对产品文档、项目页与待补充问题，输出按优先级排序的补充清单。
```
**程序把 03:54:55 那条运行摘要当成了「回复」**（「取该条消息之后第一条 agent 评论」），随即把 `pending` 置为 false；**真正的回答（03:55:06）和那一行 `建议任务：…` 被丢掉了**——`GET /chat` 里第 2 轮回复显示的是「已修复任务处置记录并标记完成；对话回复已留在评论中。」，`建议任务` 卡片也不会出现。同事在同一次运行里发多条评论是 Paperclip 同事的常见行为，不能假设「第一条就是回答」。

另外发现：`GET /chat?agent=KnowledgeKeeper` 里 `unread: true`，但 `/state` 的 `chat.agents` 是 `{}`——**同事头顶的「💬」未读气泡拿不到数据**。

## 要求
1. **回复识别规则改为（按优先级）：**
   - ① 该用户消息之后、**下一条用户消息之前**的所有 agent 评论里，**第一行以 `【对话】` 开头的**才是回复候选；有多条候选时，**把它们按时间顺序合并成一条回复**（用换行连接，合并后仍受 1500 字上限），`建议任务：` 行从合并后的文本里解析；
   - ② **不以 `【对话】` 开头的 agent 评论一律不当回复**（这类是运行摘要 / 处置记录等），不进入聊天记录；
   - ③ **回复完成的判定不能是「看到第一条候选就结束」**：要同时满足——有 ≥1 条候选，且**该同事此刻没有进行中的运行**（用已有的只读接口判断，例如 agent 状态不是 `running`；取不到就退化为「最后一条候选之后 ≥ 15 秒没有新评论」）。在判定完成之前，界面保持「思考中」，已到的候选可以先显示但标记「还在回复…」；
   - ④ **同事始终没按格式回复**（只有不带 `【对话】` 的 agent 评论）：等满 **90 秒**后，取其中**最后一条**非程序评论作为回复，并标记 `format: 'loose'`（界面提示「TA 没有按对话格式回复」）；仍然没有任何 agent 评论则按原来的 10 分钟超时处理。
2. **会话任务描述里把格式写进去**（`chat.mjs` 创建会话任务的描述文案）：「每次只发一条回复评论，第一行以【对话】开头；不要再发『已处理 / 已标记完成』之类的运行摘要评论」。**不要改任何 agent 的 AGENTS.md**（我已另行更新）。
3. **未读标记**：`/state` 的 `chat.agents` 要包含每位**有未读回复**或**有待回复消息**的同事：`{ [agentId]: { pending, unread, queued } }`（只有布尔值，不含正文）；`app.js` 里已经有读取 `v.chat?.unread` 的代码（头顶 💬），确认它能拿到数据（**只在 `app.js` 里确认读取路径，不要改 `app.js`**；如果读取路径需要改，写进汇报，由我决定）。
4. 不改变：额度、扫描、排队、会话任务管理、转任务、隔离、默认关闭等已验收行为。

## 测试（`tests/chat.test.mjs`，保持原有断言，不得放宽）
- **用上面的真实时间线做用例**（运行摘要 + 真回答 + 建议任务行）：回复 = 真回答，`建议任务` 被解析出来，运行摘要不进入记录。
- 多条候选合并（两条都以 `【对话】` 开头）；候选之间夹着非候选评论；用户在回复完成前又发了下一条消息（后一条消息之后的评论不能算前一轮的回复）。
- 完成判定：只有候选但同事仍在运行 → 仍是「思考中」；运行结束 → 完成；取不到运行状态 → 15 秒静默后完成。
- 松散格式：只有不带前缀的 agent 评论，90 秒内不当回复，90 秒后取最后一条并 `format: 'loose'`；程序自己的评论（含 `【对话】` 开头但由程序发出的那条用户消息）不能被当成回复。
- 10 分钟超时、不重发、重启后保留状态仍然成立。
- `/state` 的 `chat.agents` 字段（有待回复 / 未读 / 排队各一例），且**不含任何正文**（构造包含对话原文的数据，断言序列化后的 `/state` 里找不到原文）。
