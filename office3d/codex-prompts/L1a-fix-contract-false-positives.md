## 缺陷与要求
1. **资金误判（最重要）**：`validateContract` 里 `moneyText` 用了 `contract._sourceText`（整个契约原文），所以**「禁止: 读取密钥」这种安全禁令**命中 `MONEY_RE`（含「密钥」），被强制要求风险等级 = 资金。我们几乎每张任务卡的「禁止」里都会写密钥 / 口令，这会让绝大多数任务被误判为资金类。
   - **要求**：资金类判定只看 **项目、目标、交付物、允许修改** 四个字段（**不看「禁止」「工具权限」「验收标准」**）；`isLowRiskBatchEligible` 里的同类判定同样处理。
   - 测试：`禁止: 读取密钥 / 不得提现` 且风险等级 = 低 → **通过**；`目标: 修改提现逻辑` 且风险等级 = 低 → `money_mismatch`；`交付物: 迁移脚本` 且风险等级 = 低 → `money_mismatch`（迁移 / 鉴权 / IAM 仍按 `MONEY_RE`）。
2. **「依赖: 无」被拒绝**：模板写的是「`<无或任务编号>`」，但校验把「无」当成非法任务编号（`invalid_dependency`）。
   - **要求**：依赖字段为 `无 / 没有 / none / -` 视为空依赖，通过；其他项仍必须匹配任务编号格式。测试覆盖「无」「无, CMP-301」（后者仍视为混用，报错或把「无」忽略，**二选一并写测试说明**）。
3. **重复契约区块被放过**：描述里出现**两个** `【任务契约】` 区块时，校验通过，且不知道取哪一个，存在「后写覆盖前写」的绕过。
   - **要求**：`parseContract` 发现多个区块时返回 `errors` 含 `multiple_contracts`（且 `validateContract` 因此 `ok:false`）；测试一例。
4. **过短的验收标准**：`验收标准: - 好` 通过。
   - **要求**：一条验收标准**去除空白后少于 6 个汉字（或 12 个英文字符）视为不可检查**；**至少一条**必须满足长度并包含可观察动词或结果词之一（如：显示、返回、通过、拒绝、生成、保存、小于、大于、等于、不超过、≥、≤、无报错、测试全过；列表你自己定并写进常量 `CHECKABLE_HINTS`）。测试：`- 好` 失败、`- 页面显示等待时长且测试通过` 通过、`- 完成` 仍失败。
