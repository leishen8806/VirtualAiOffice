# S2-15-console-sharpness：调度中心 `dr-console.html` 大屏清晰度（Trae，仓配线；**前置：S2-13b 已验收**——它也在改 `dr-console.*`；约 1.5 小时）

**董事会 2026-10-22 反馈（约 2000 px 宽的屏幕截图）：「太模糊，清晰度太低了」。**

## 我查到的原因（读了代码与素材）
1. **中间全景图分辨率不够：** `.panorama` 与 `.sceneThumb` 用的 `assets/demo/dr-campus-reference.jpg` 只有 **1672×941、247 KB**；连它的来源（董事会的概念图 PNG）本身也只有 1672×941。全景区在 2000 px 宽的屏幕上被放大约 1.2–1.5 倍，再按 `cover` 裁切，**必然发糊**；247 KB 的 JPEG 二次压缩又带来块状噪点。
2. **「园区实景视角」与右下「视频监控」四宫格是同一张图的局部放大：** 把 1672 px 的图里一小块放大到几百像素宽，放大倍数 3–6 倍，**最糊的就是这几块**。
3. **字号是固定像素：** KPI、表格等用固定小字号，大屏上字小且被缩放后发虚；没有按屏幕宽度自适应。
4. Canvas：流动路径层已按 `devicePixelRatio`（上限 2）绘制，不是主因；**柬埔寨物流网络小地图需确认同样按 DPR 绘制**。

## 要做的事
1. **素材（先用现有最好的，再等高清版）：**
   - 立即：全景改用**无损或高质量**版本（由董事会原图 PNG 导出 WebP 质量 ≥ 90 或 JPEG 质量 ≥ 92；**不改构图、不加特效**），文件放 `assets/demo/`，旧文件保留不删；
   - 预留高清槽位：页面按 `image-set()` / `srcset` 同时支持 `dr-campus-reference@2x`（3840×2160）——**高清原图由董事会用 GPT 生成后提供**，到位后只换文件不改代码；文件缺失时自动回退当前版本。
2. **四宫格与「园区实景视角」不再裁切放大同一张图：** 每格改为**独立的图片槽位**（`assets/demo/dr-cam-*.webp`，各自 ≥ 960×540）；在新图到位前，用**整图缩略**（不放大局部，`contain` 或等比缩小）作为占位，标签保留「模拟 / 示意」。**不得用任何生成视频或滤镜「锐化」冒充高清。**
3. **大屏自适应字号：** 全页字号改为随视口宽度缩放（例如 `font-size: clamp(12px, 0.62vw, 20px)` 一类，**按 1920 与 2560、3840 三档实测调整**），KPI 数值、表格行、面板标题在三档宽度下都清楚、不溢出；移动端规则（`max-width:767px`）不变。
4. **小地图与所有 Canvas 按 DPR 绘制**（上限 2，大屏模式可到 3，需写出取舍）；窗口尺寸变化时重绘，不拉伸位图。
5. **不改数据、不改动态逻辑、不改 W1 / W2 / W3 热点与导航**；默认关闭的动态层行为不变。

## 验收（Playwright，用完即删截图）
- 1920×1080、2560×1440、3840×2160 三档各截一张（`deviceScaleFactor` 1），**同一区域放大对比**改前改后：全景、四宫格、KPI、表格文字；
- 写出实际使用的图片像素尺寸与文件大小；网络请求只多出新的图片文件，无 `/api` `/state` `/act`；
- 控制台 0 错误；全量 `node --max-old-space-size=2048 --test --test-timeout=60000 --test-concurrency=2 tests/*.test.mjs` 全过。
