# T14-handoff-package：断点交接包（第 2 条）——被打断、阻塞、换人时，不让后来的人从头摸索

先读 `_common.md`。**本任务的例外规则：** 允许新增 `handoff.mjs`、`tests/handoff.test.mjs`；允许修改 `server.mjs`（**只限第 5 节接线**，不要碰局域网访问码、`hostOk`、大屏令牌、`act()` 已有分支、静态文件白名单）、`governance.mjs`（**只限**加一个「交接」分区的数据）、`ui.js`（**只限**治理中心里加一节「交接」）、`README.md`。**不要改** committee / standup / acceptance / blocked / memory / wall / workload / rework 等其它模块（T6 的改派在 `blocked.mjs` 里，**不要碰**；本任务只在「发现任务换了负责人」之后转交）。**不得向 Paperclip 发任何会改变任务状态、负责人、依赖的请求**；唯一允许的写入是第 3 节规定的带标记评论。不新增依赖。备份到 `office3d-backup-handoff`（办公室目录没有 Git）。**不要与其他 Codex 任务同时进行。** **知识库模板和同事的 AGENTS.md 由 Claude 另行维护，你不要改。**

【背景】同事（agent）被打断（运行失败 / 超时 / 取消）、任务转阻塞、或任务换了负责人之后，后来的人只能翻一长串评论重建现场，常常重复做、或做漏。Paperclip 自带 `successfulRunHandoff` 字段，但目前**没有任何任务在用**（实测 0 个）。我们要一个**标准化的交接包**，由同事在这些时刻写在评论里，程序负责识别、提醒、转交。格式（Claude 会写进知识库 `流程/模板/交接包.md`，你按这个解析）：

```
【交接包】对象版本：<Git 提交号 / 文件 SHA-256>
已完成：AC-1 ｜ AC-2（逐项，写明证据在哪个评论 / 文件）
未完成：AC-3 ｜ …
下一步：<下一个人能直接执行的一步，含命令或文件路径>
阻塞与解除条件：<没有则写「无」；有则写明类型和解除条件>
工作位置：<worktree 路径 / 分支 / 未提交的改动在哪>
不要重做：<已经验证过、重做只会浪费的事>
```
字段名容忍全角 / 半角冒号和前后空白；**缺任何一个字段视为不完整**（给出缺哪些）。

## 1. 必须有交接包的时刻（程序只读判断，不推断）
对状态为 `in_progress` / `blocked` / `todo`（被退回）且负责人是 agent 的任务，满足下列任一**触发条件**，就检查触发之后是否有（来自该任务当前或前任负责人的）完整交接包：
- **T1 运行中断**：该任务关联的最近一次运行状态为 `failed` / `timed_out`（`cancelled` 不算，沿用 T4 的 `isFailure` 口径，复用）且任务仍未结束；
- **T2 转阻塞**：任务状态变为 `blocked`（时间取 `blockedTransitionAt`）；
- **T3 换人**：任务负责人变化（需要自己记录上一轮扫描看到的负责人；第一次见到的任务不算换人）；
- **T4 长停留**：任务 `in_progress` 且 **24 小时内没有任何新评论和新运行**（沿用 `blocked.mjs` 里「负责人动作」的判断思路，但**不要修改它**，在本模块里自己实现，并忽略程序自己的标记评论）。
先**只读**检查 Paperclip 的 `successfulRunHandoff` / `executionState` 字段在真实任务上的含义（取 3 个有运行记录的任务看），把结论写进汇报；**不要依赖这些字段**，也不要写它们。

## 2. 交接包解析与校验（`handoff.mjs` 纯函数）
- 从评论里找最近的 `【交接包】`，解析各字段，输出 `complete` / `missing:[字段]` / `version`（对象版本字段原文）。
- **脱敏**：输出前对所有文字走 `wall.mjs` 的 `redactText`（金额、IP、邮箱、链接、疑似密钥打码，复用，不要另写）；工作位置里的本机路径保留，其余按规则。
- 评论正文超长时只保留各字段前 300 字。

## 3. 动作（全部默认关闭，`handoff.json` 的 `enabled:false` 为总开关；文件不存在按关闭处理）
- **缺交接包**（T1/T2/T4）：对**仍在岗、非 paused 的 agent 负责人**发**一条**评论（首行 `【交接巡检】`）：说明触发原因、要求按模板补写交接包；同一任务同一触发每 24 小时最多一条；T4 只在上班时间提醒；**资金类任务**（`standup.mjs` 的 `MONEY_RE` 口径）只在治理中心显示和通知董事会，**不自动发评论**。
- **换人**（T3）：新负责人没有看到前任交接包的话，程序发一条评论（首行 `【交接包转交】`），把前任**最近的完整交接包**（脱敏、≤1500 字，保留字段结构）原样转交，并写「这是前任留下的交接包，请先核对对象版本再继续」；没有完整交接包就写「前任没有留下完整交接包，缺：…」并列出最近 3 条前任评论的时间（不贴正文）。每次换人只转交一次。
- 评论会唤醒负责人：**每轮最多处理 6 个任务**，每个岗位 1 小时内最多收到 3 条巡检评论，**汇报里评估多余运行风险**。
- **不改状态、不改负责人、不替任何人写交接包内容。**

## 4. 完整性之外：新鲜度提示（只提示）
交接包里的「对象版本」如果是 Git 提交号且任务评论里之后出现了更新的 `【验收证据】` 对象版本不同，在治理中心标「交接包版本可能已过期」。**只比较两个字符串，不读仓库、不执行 git**（读仓库核对版本是另一个任务 T15 的职责）。

## 5. 接线（`server.mjs`，只允许这些）
1. `import { createHandoff } from './handoff.mjs'`，仿照 `createBlockedPatrol` 创建；传入 `get`、`send`、`notify`、`dutyOn`、`now`、`isMoney`、`agents`（名单和状态）。**重启后第一次扫描等 5 分钟**，之后每 30 分钟扫一次（评论和运行按任务更新时间缓存，只读 GET）。
2. 新增只读 `GET /handoff`：每个触发任务的编号、标题、负责人、触发类型和时间、交接包是否完整及缺项、是否已提醒 / 转交、是否可能过期；放在现有访问控制之后，**大屏令牌设备 403**（沿用 `API_PATHS`）。
3. `/state` 里加 `handoff: h.view()`（摘要：缺失数、已转交数、最近 10 条处理记录；不含评论正文）。
4. `act()` 里**只新增**一行 `handoff_run`（董事会手动扫描一次；局域网只读时沿用现有 403），并把 `handoff_` 加进已有的「结果透传」前缀判断。
5. 状态保存在 `handoff.json`（上一轮负责人、已提醒 / 转交记录），原子写入，损坏时视为关闭并在 `/state` 提示。

## 6. 界面（`ui.js`，治理中心加一节「交接」）
缺交接包的任务置顶（按触发后经过的时间排序），每行：编号、标题、负责人、触发类型、经过多久、缺哪些字段、是否已提醒；已转交的显示转交时间；可能过期的灰标。所有文字 `esc()`，窄屏可用，局域网只读时「立即扫描」置灰。
