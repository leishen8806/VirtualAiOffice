# R3-3b-shell-rework：`?layout=3` 外壳返工（天空 / 地面被拆光、绿化带与隔断缺失；Codex 会话一；约 1.5–2 小时）

**背景：** R3-3 的数字达标（外壳增量 6 calls、约 2300 三角形，全量测试 1077 全过，控制台 0 错误），但**我在真实浏览器里看到的画面不合格**，R3-3 不予放行，按本卡返工。**不要重做已通过的部分**（LAYOUT_V3 数据、遮挡纯函数、`?layout=2` 与默认页面不变、`app.js` 接线结构）；只改下面几处。
**我的实测（`http://office.localhost:3200/?layout=3`，1280×720，高档）：**
1. 场景四周是**一片纯黑**；`scene.background` 为 `null`，场景根节点只剩 3 盏灯、`office3-root`、`merged-static`。
2. 外墙是一块块白色实体墙，看不到玻璃隔断，也看不到暖色（办公区暖色令牌）。
3. 外框外侧一圈 2.5 m 绿化缓冲带**没有可见表现**（现有代码只画了 0.45 m 宽的细条）。
4. 低机位的画面几乎只有白色墙面，看不到室内。

## 根因（我读了代码）
`office-v3-modules.js` 的 `demolishLegacyScene(scene, keep)` 对 `scene.children` 做**白名单式拆除**：除相机和 `keep` 里的灯之外**一律 `removeFromParent()`**——连 `env.js` 建的天空、远景地面、远景树 / 路灯一并拆掉了。任务卡要求的是只拆**冲突物**：rev2 外壳与家具与吧台、旧中庭 / 前厅、旧 DR 广场内部（24×14 矩形）及配套、广场西侧旧仓库外壳（`x=-42…-14, z=17…29`）、与新外框 / 广场 / 绿化带冲突的树、路灯与铺装。

## 要做的事
1. **拆除改为「点名拆」：** 不再遍历 `scene.children` 全删。`app.js` 里在 `createEnvironment`（env.js）调用前后已经有 `sceneBeforeEnvironment / environmentRoots` 的记录（NAV-1d 加的），**复用它**：环境根节点（天空、远景地面、雾、背景）一律保留；对**环境里与新布局冲突的具体对象**（落在 `LAYOUT_V3.site` 内的树、路灯、铺装）按名称或位置判定后单独隐藏 / 移除。`demolishLegacyScene` 改为接收「要拆除的对象集合」，而不是「要保留的集合」。写测试：给定一个模拟场景（天空、地面、一棵站在新外框里的树、一棵在站点外的树、旧外壳、旧家具），断言天空与地面保留、站点内冲突物被移除、站点外的树保留。
2. **背景与光照恢复：** `?layout=3` 下的天空 / 背景 / 雾与默认页面一致（对比 `scene.background`、`scene.fog`、天空网格存在与否）；黑色背景是回归，必须消失。
3. **绿化缓冲带做成真正的 2.5 m 带：** 沿 `LAYOUT_V3.greenBuffer` 一圈铺 2.5 m 宽的草地 / 铺装带，加低矮灌木与花池的**程序化占位**（实例化，几何体共用，**不增加 calls**，只是增加实例）；暖色令牌取自 `office-theme-v2.js`，不得出现深蓝科技色。门前广场开口处断开。
4. **隔断改为暖色框 + 玻璃：** 办公室内隔断高 2.2 m、玻璃通透度沿用令牌 0.62；会议 / 董事会下部 0.9 m 实体墙 + 上部玻璃；外墙是暖色实体（不是纯白）。**列出实际使用的颜色令牌与十六进制，并用截图对照暖色基调。**
5. **遮挡策略要看得见室内：** 低机位与跟随机位（`LAYOUT_V3.cameraDefaults` 的 `wallMode`）下，靠近相机一侧的外墙淡出 / 下沉，**必须能看见室内的玻璃隔断与地面分区**；全景 / 俯视 / 等距保持整墙。
6. **预算不变：** 同机位同画质（高 / 低各一）成对测量，外壳 + 绿化带增量高档 ≤ +6 calls、≤ +20k 三角形，低档 ≤ +3 calls（切换 `office3-root.visible` 取精确增量）；若超出，按「植物占位 → 花池 → 地面分区」顺序降级并如实写出。
