# T6-blocked-patrol：每 3 小时的阻塞巡检（提醒负责人 → 委员会重新评估 → 再分配）

先读 `_common.md`。**本任务的例外规则：** 允许新增 `blocked.mjs`、`tests/blocked.test.mjs`；允许修改 `server.mjs`（**只限第 4 节列出的接线**，不要碰局域网访问码、`hostOk`、大屏令牌、`act()` 里已有的任何分支、静态文件白名单）、`ui.js`（只加「委员会」弹窗里一节）、`README.md`。**不要改** `committee.mjs` / `standup.mjs` / `acceptance.mjs` / `telegram.mjs` / `wall.mjs` 的逻辑（只允许 `import { MEMBERS, BACKUP } from './committee.mjs'`）。**验证时不得向 Paperclip 发任何写请求**（POST / PATCH / PUT / DELETE），也不得触发真实巡检：全部写逻辑只用模拟接口测试；真实数据只通过你新增的只读 `GET /blocked/preview` 看。第一次真实运行由 Claude 在你交回、验收之后做。

【背景】Paperclip 会把「已指派、进行中、但没有可运行路径」的任务自动改成「阻塞」，之后**没有任何机制叫醒它们**，晨会又会把阻塞任务剔除，结果 CMP-12、CMP-130 这类审查任务被遗忘了两天。董事会要求：**每 3 小时巡检一次阻塞任务；没有未满足依赖的，提醒负责人，提醒无效就交给委员会重新评估后再分配。** 对应流程文档《任务管理流程》第 7 节「阻塞：写明类型和解除条件」（先读 `E:\VirtualAIOffice\knowledge\流程\任务管理流程.md` 第 3、7 节和 `E:\VirtualAIOffice\knowledge\流程\晨会流程.md`；代码风格和做法参考 `standup.mjs`、`acceptance.mjs` 及它们的测试）。

## 1. 什么算「需要巡检的阻塞任务」
- Paperclip 任务 `status === 'blocked'`，且**没有未满足的依赖**：`GET /api/issues/{id}` 的 `blockedBy` 为空，或其中全部是 `done` / `cancelled`。**有未满足依赖的一律跳过**（它们在等上游，不是被遗忘）。
- 读取该任务**最近一条以「阻塞：」开头的评论**，解析第一行 `阻塞：<类型> | 解除条件：… | 下次检查：…`。类型只有五种：依赖未完成 / 待授权或业务决定 / 额度登录环境异常 / 验证失败 / 范围冲突或文件占用。
  - 「下次检查」能解析成**未来的时间**（如 `2026-10-19 13:00`，金边时间）→ 跳过，等到点。解析不出（如「收到依赖完成唤醒后立即复核」）→ 当作没有时间。
  - 没有「阻塞：」评论或格式不对 → 类型记为「未说明」。
- 只巡检**上班时间**（读 `../workhours/workhours.json` 的上班日和时段，周日也上班）；负责人状态是 paused 的跳过；负责人是真人（`assigneeUserId`）的跳过。

## 2. 阶梯（每个任务各自的状态，存在 `blocked.json`）
- **第 1 步 提醒**：首次在巡检里发现、且满足第 1 节 → 在任务里发一条评论并唤醒负责人（评论即唤醒；**不要改状态**）。评论内容按类型：
  - 依赖未完成但依赖其实已完成 / 验证失败 / 范围冲突 / 未说明：提醒「已阻塞超过 N 小时且没有未满足依赖，请重新核对前置条件后继续，或按格式写明阻塞类型、解除条件和下次检查时间」。
  - **额度登录环境异常**：先看运行健康（复用 `server.mjs` 里的 `healthReport()` 的 `incidents`）；仍有未恢复的额度 / 登录事件 → 本轮跳过；已恢复 → 提醒。
  - **待授权或业务决定**：**不提醒负责人、不进委员会**，只在 Telegram 通知董事会一次（同一任务 24 小时内最多一次），列出任务编号和「要决定什么」。
- **第 2 步 委员会重新评估**：上次提醒后至少过了一轮巡检（≥3 小时），且这期间**负责人没有任何动作**（该任务没有新的非系统评论、没有新的运行记录、状态没变）→ 纳入委员会批次。
- **第 3 步 交还人工**：委员会处理之后再过一轮巡检，仍然阻塞且没有动作 → 通知董事会一次「需要人工」，状态记 `human`，**此后不再对该任务做任何自动操作**。

## 3. 委员会重新评估（复用现有委员名单和投票方式）
- 一批最多 6 项，同一时间只开一批；给 `MEMBERS` 里 5 位委员各开一张投票任务（项目「运营与知识库」，间隔 **15 秒**逐张创建，防止 git 工作树抢锁）；**负责人回避**（该任务的负责人是委员时，由 `BACKUP` 顶替）。
- 提示语要求（吸取过的教训）：**规则和投票格式放最前面**，每项任务的摘要（编号、标题、负责人、阻塞类型、最近一条评论节选）按预算压缩，整段不超过 3600 字，**最坏情况（6 项长评论）规则也要完整**，要写测试。
- 每项四选一：`CONTINUE`（让原负责人继续，附一句建议）/ `REASSIGN <岗位名>`（改派给谁）/ `SPLIT_OR_CANCEL`（建议拆分或取消）/ `ESCALATE`（需要董事会）。格式：`VOTE <序号>: CONTINUE|REASSIGN <岗位名>|SPLIT_OR_CANCEL|ESCALATE | 理由`。解析要容忍全角冒号、大小写、`REASSIGN Backend1` 里的岗位名。
- **统计**：5 张投票任务都结束或 30 分钟到点。某个动作拿到 ≥3 票（`REASSIGN` 要 ≥3 票指向**同一个岗位**）且没有 `ESCALATE` → 执行；有任何 `ESCALATE` → 通知董事会；没有形成多数 → 默认 `CONTINUE`（再唤醒一次）。**一张有效票都没有** → 本批作废，不执行任何动作，任务保持原状，下一轮巡检再来（和晨会、超时验收一致：不能把「没人投」当成任何结论）。
- **执行（由程序做，不靠 agent）**：
  - `CONTINUE`：评论附委员会意见并唤醒原负责人。
  - `REASSIGN`：先校验——目标岗位存在、不是 paused / error、手上未完成任务 ≤2、不是任务原负责人；**资金类**（任务描述命中资金类关键词，复用 `standup.mjs` 里 `MONEY_RE` 的口径，不要复制粘贴一份不同的）只能改派给 GoSenior / DBEngineer，并且**必须先建董事会审批**，批准后才改派；校验不过 → 改为通知董事会。校验通过 → `PATCH` 负责人、状态改回 `todo`，评论写明「委员会 X/5 同意改派，原因：…」。**不得**越过未完成依赖（不要用 force）。
  - `SPLIT_OR_CANCEL`：**程序绝不自动拆分或取消**，只通知董事会并附委员会意见。
  - `ESCALATE`：通知董事会。

## 4. 接线（`server.mjs` 里只允许做这些）
1. `import { createBlockedPatrol } from './blocked.mjs'`，仿照 `createStandup` / `createAcceptance` 创建并 `start()`，传入 `get` / `send` / `notify`（Telegram 通知，同其他模块）/ `dutyOn`（取自 `world().duty.on`）/ `healthReport`。
2. 新增只读 `GET /blocked/preview`：**干跑**，返回「如果现在巡检会怎么处理」——每个候选任务的编号、标题、负责人、阻塞类型、将执行哪一步、被跳过的原因；**不得产生任何写操作**。放在现有访问控制之后（局域网设备同样要过访问码；大屏令牌设备不得访问，沿用现有的 `API_PATHS` 方式把它加进去）。
3. `/state` 里加 `blockedPatrol: patrol.view()`（上次巡检时间、下次时间、各步骤计数、当前批次状态、最近 10 条处理记录）。
4. `voteSessions` 里加一项 `kind: 'blocked'`（批次投票中时，委员像晨会、超时验收那样走进评审室，写法照 `server.mjs` 里 acceptance 那一段）。
5. `act()` 里**只新增**一行：`blocked_run`（董事会手动立即巡检一次）；并把 `blocked_` 加进已有的「结果透传」前缀判断。
6. `blocked.json` 里 `enabled: false` 是**总开关**（关闭后只显示状态、不做任何写操作）；文件不存在时默认开启，但**重启后第一次巡检要等 5 分钟**，不要一启动就动手。

## 5. 界面（`ui.js`，只加一节）
「委员会」弹窗里加「阻塞巡检」：上次 / 下次巡检时间、总开关状态、当前各阶梯里的任务（编号、标题、负责人、阻塞类型、在第几步、等了多久）、最近的处理记录；一个「现在巡检一次」按钮（调用 `blocked_run`，局域网只读时按现有方式置灰）。所有文字用 `esc()`。窄屏要能看。

## 6. 防止巡检自己制造混乱
- 每轮最多处理 6 个任务（超出的留到下一轮，按等待时间从长到短）；同一任务 3 小时内最多被提醒 1 次；连续 2 轮提醒无效才进委员会；进过委员会的任务 24 小时内不再进。
- 巡检写的评论必须以固定标记开头（如 `【阻塞巡检】`），**判断「负责人有没有动作」时要忽略这类系统评论**，否则巡检会把自己的提醒当成负责人的动作。
- 所有评论遵循知识库《任务管理流程》第 7 节的格式；中文，简短。
