# T10-low-end-performance：让普通电脑也能流畅打开智序工场 3D 页面（画质分档 + 渲染减负）

先读 `_common.md`。**本任务的例外规则：** 允许修改 `app.js`、`env.js`、`people.js`、`office-partitions.js`、`landmarks.js`、`wing.js`、`office-layout.js`（**只限**渲染 / 合并 / 光源 / 阴影相关，**不改任何坐标、座位、房间尺寸、走道**）、`director.js`（只限动画更新频率相关）、`index.html` 与 `ui.js`（只加「画质」菜单一项）、`README.md`、`tests/` 下新增测试；允许新增 `quality.js`。**不要改** `server.mjs` 和所有 `*.mjs` 业务模块、局域网 / 令牌相关代码。**不改变任何功能行为**：25 位同事的走位、休息区、会议室、投票会、晨会、点地面走路、小地图、大屏 `wallGo`、搜索跳转、老板桌、天气都要保持。纯前端，**不需要重启服务**，验收时 Ctrl+F5。备份到 `office3d-backup-low-end`（办公室目录没有 Git）；在当前版本上改，不要用旧备份覆盖。

【背景和实测基线】董事会反馈：「一般的电脑跑不动智序工场的 web 端」。我在 RTX 5070 Ti 机器上量到（1024×768，DPR 1）：
- **每帧绘制调用 `renderer.info.render.calls` = 1784**；渲染三角形 96,021（场景总计 318,067）；
- 网格 1018 个、几何体 268、纹理 54；
- **灯 18 盏**；开阴影的物体 334 个，`shadowMap.enabled = true`、`autoUpdate = false`（阴影靠手动刷新）；
- **带骨骼人物 26 个、骨骼共 2082 根**（每帧 CPU 做骨骼动画）；
- 本机 GPU 占用：一个办公室标签页就占 ~69%（RTX 5070 Ti），说明这页对普通核显（Intel UHD / 老款 MX / 集成显卡）和 8GB 内存的笔记本很可能是灾难。
**瓶颈判断（请你先实测验证再动手，别照单全收）：** 绘制调用过多（CPU 端提交开销）、灯和阴影的像素着色开销、骨骼动画的 CPU 开销、持续 60 帧渲染从不降频。

## 目标（按重要性）
1. **画质三档**：`low` / `medium` / `high`，菜单里可手动选（「设置」组里加一项「画质」），选择记在 `localStorage`（读写包 try/catch）；URL 参数 `?q=low|medium|high` 可强制，优先级最高。**`high` = 当前效果，不得有任何视觉退化。**
2. **自动选档**：首次进入没有记录时，先按 6 秒预热期的平均帧耗时 + 设备信号（`navigator.hardwareConcurrency`、`navigator.deviceMemory`（可能为空）、`WEBGL_debug_renderer_info` 里的 GPU 名是否含 Intel / UHD / Iris / Mali / Adreno / SwiftShader 等集成 / 软件渲染关键字）决定起始档；之后在运行中如果连续 10 秒平均 < 24 FPS 则降一档（最多降到 low，**同一会话降档后不再自动升回**，避免来回抖动、不闪屏）。已有的自适应 DPR（`frame()` 里，预热 6 秒后才调整，`?fixeddpr=1` 可关）要与档位协同，不能互相打架。降档时画面不能闪烁、不能重新加载。
3. **各档目标（在 1280×720 俯视和默认镜头下实测，写进汇报）：**
   - `high`：同现状。
   - `medium`：绘制调用 ≤ 900；灯 ≤ 8；阴影保留但分辨率减半、仅主要建筑 / 人物投影；DPR ≤ 1.25；帧率上限 60。
   - `low`：绘制调用 **≤ 500**；灯 ≤ 4（其余用环境光 / 半球光 / 烘焙感的自发光材质代替）；**无实时阴影**（用人物脚下的简单圆形假阴影贴片代替）；DPR ≤ 1；帧率上限 30；远处人物骨骼动画降频到 15 Hz；关闭雨 / 雷达粒子等装饰性粒子（天气文字和图标保留）；纹理尽量降采样。
4. **渲染减负的具体手段（逐项评估，做了的写明前后数字，没做的写原因）：**
   - **合并静态几何**：现在已有 `mergeStatic`；检查为什么仍有 1018 个网格 / 1784 次调用——哪些类别（桌椅、显示器、窗框、地毯、植物、墙面、文字牌）没合并或因材质不同没合并，按材质分组合并；人物、会动的、需要点击的除外。
   - **实例化**：重复物（椅子、显示器、桌子、植物、灯具）用 `InstancedMesh`，保持碰撞和点击拾取仍然可用（现有 `furnitureCollision` / 拾取逻辑要继续对）。
   - **灯光**：18 盏灯逐盏盘点（类型、位置、是否投影、对画面的贡献）；`medium` / `low` 下合并或关闭；灯数量变化要避免触发着色器重编译卡顿（预先设计好每档的灯集合，切档时一次性切换，不要运行时增删）。
   - **阴影**：`high` 保持；`medium` 减半分辨率；`low` 关闭实时阴影。阴影手动刷新的频率在 `low` 下降低。
   - **骨骼动画**：人物按距相机距离做 LOD——远处降到 15 Hz 更新或暂停空闲人物动画（但走动中的人物不能抖动、不能穿模；坐姿 / 说话 / 转身的衔接不能破）；视锥外不更新骨骼。
   - **视锥剔除与可见性**：确认静态合并体没有关闭 `frustumCulled` 导致整栋楼每帧都被提交；大物体分块（例如按房间分块合并）使剔除有效。
   - **帧率与后台**：标签页不可见时完全暂停渲染循环（`document.hidden`），可见但 30 秒无操作且无动画事件时降到 10 帧（有人物走动、投票会、说话气泡时恢复）；`low` 帧率上限 30。大屏嵌入模式（`?wall=1`）默认 `high` 且不进入无操作降频，但自动选档的降档保护仍然有效。
   - **纹理与材质**：检查 54 张纹理的尺寸（>1024 的在 `low` 降采样）；材质类型（能用 `MeshLambertMaterial` / `MeshBasicMaterial` 的地方，在 `low` 下替换 `MeshStandardMaterial`——注意颜色空间一致，视觉差异要在汇报里贴对比图）。
   - **DPR 与分辨率**：`low` 下 DPR ≤ 1；超大屏幕（4K）下 `low` / `medium` 用渲染缩放而不是原生分辨率。
5. **可观测**：画质菜单里显示当前档位、当前 FPS、`render.calls`、三角形数；`?perf=1` 在角落叠加一块小面板（FPS、帧耗时、calls、triangles、灯数、档位、降档原因）。不要常驻显示。

## 验收（缺一不通过，**数字必须是真实实测，没测到的写「未验证」**）
- `node --test tests/*.test.mjs` 全过，**不得为了通过而放宽已有断言**；新增 `tests/quality.test.mjs` 覆盖纯函数：档位选择（设备信号组合）、降档判断（连续 10 秒 < 24 FPS、不会自动升回、预热期不判断）、URL 参数优先级、localStorage 损坏时的回退。
- `node --input-type=module --check < 文件.js`（所有改过的浏览器模块；不要用 `node --check x.js`）。
- **每档实测表**（打开 `http://office.localhost:3200/?q=low|medium|high`，Ctrl+F5，1280×720，俯视和默认镜头各一次，各档截图）：`calls`、`triangles`、灯数、阴影状态、DPR、2.5 秒 rAF 平均 FPS。`high` 与改前的差异要说明（应当没有视觉差异，calls 可以更低）。
- **弱机模拟**（真机无法获得，只能代理，**如实标注是代理**）：① 用 Chrome DevTools Protocol（`Emulation.setCPUThrottlingRate` 设 4×、6×）；② 用软件渲染（`--use-gl=swiftshader` / `--enable-unsafe-swiftshader`，本机 Playwright Chrome 已是这样启动）打开页面；报告每档在这两种条件下的 FPS 和帧耗时，以及自动选档是否降到合适的档位。
- **不退化清单**（逐项验证并写出方法和结果，三个档位都要做）：25 位同事各就各位、同事互访（任意两人走一趟）、去休息区、去会议室 / 评审室投票会入座、董事会找苏晨、点地面走路、小地图点击跳转、搜索跳转区域、区域镜头按钮、大屏 `wallGo` 各 key、天气文字和图标、控制台无报错、点击人物 / 点击家具的拾取仍然正确（实例化后最容易坏）。
- **切档**：高 → 低 → 高 不闪屏、不重载、不丢失人物位置和气泡；刷新后沿用选择。
- **GPU 占用对比**：用 Windows 性能计数器（`\GPU Engine(*)\Utilization Percentage`，按 Chrome GPU 进程 pid 求和，3 次采样平均）测 `high` / `medium` / `low` 前台打开时的占用，和标签页切到后台时的占用，贴数字。
- 汇报里明确：每一项手段做了没有、前后数字；**哪些在真实的低端电脑（Intel 核显、8GB 内存）上没有验证**；`low` 档相比 `high` 在视觉上丢了什么（逐条列）。**不要承诺「普通电脑一定流畅」，只报告测到的。**
