## 总原则（沿用 T17 / 经济规划的口径）
- **没有真实数据就显示固定空态文案，不得编造**：没有真实等待状态不得播放等待动画；没有公告不得显示示例文字；没有访客记录显示「尚无访客记录」。
- **只显示数量和安全短句，不显示任务正文、问题正文、错误详情、票据提示语、IP、设备标识。**
- 所有显示文字经 `esc()` 转义或使用 `textContent` / Canvas `fillText`，**禁止 `innerHTML` 拼接外部数据**（公告文本是用户手写的，更要转义）。
- 局域网只读设备和大屏令牌设备：**不显示任何编辑入口**（公告编辑、交办箱）；沿用现有的权限判断（`/state` 里已有的本机 / 只读标记），**不要自己再写一套鉴权判断**。
- **不涉及钱**：此阶段 A1 / A2 / B0–B3 仍只是装饰；不写余额、价格、「购买成功」。

## 要做的事（逐项对应规划第 4 节）
1. **今日出勤板**（`foyer-panel-attendance`）：数据 `/state.world.duty` + `/state.agents[]`，格式 `{at,onDuty,on,off,paused}`（上班且 `idle/running` 计在岗；非上班时非暂停人员计下班；`paused/error` 单列）。每 3 秒随 `/state`；无数据显示「出勤数据同步中」。**口径写成 `foyer-panels.js` 里的纯函数并单测**，并与办公室顶部"25 在岗"等现有数字交叉核对一致。
2. **待你回答 / 待验收**：`question = count(waiting[].kind==='question')`、`review = count(kind==='review')`，另显 `pendingApprovals` 数字；无则「当前没有待处理事项」。只显示数量；点击沿用现有本机任务面板（**不新增面板**，局域网 / 大屏只读不可点）。
3. **今日晨会结果**：`/state.standup` 只取 `state`、通过 / 剔除数量和安全短句；不展示候选正文、票据提示语、内部评论；无则「今天还没有晨会结果」。
4. **里程碑**：数据来自 `/wall/data.milestones`（项目名、下一里程碑名、到期日、完成比例），**每 30 秒读一次，且只读 `wall.mjs` 已脱敏的视图**；注意**大屏令牌设备访问 `/wall/data` 的方式**与本机 / 局域网不同，先读 `server.mjs` 现有行为（只读），按现有权限取数，**不要为此改服务端**；取不到或没配置显示「尚未配置里程碑」。
5. **董事会手写公告**（`foyer-panel-notice`）：读 `GET /foyer` 的 `announcement`（**局域网只读设备可读**）；**仅本机**在点击公告墙后弹出编辑弹窗（`ui.js` 里新增 `openAnnounce`，仿现有 `open…` 弹窗的风格与 `esc()`）：文本框 + 字数（1–120，按 Unicode 码点算）+ 保存 / 清空；保存调用 `/act` 的 `foyer_announce`，清空调用 `foyer_announce_clear`；**服务端 422 时只显示类别提示，不回显原文**，429 / 403 给出明确中文提示（「今天保存次数已达上限」「公告功能未开启」）；**公告功能总开关关闭时，编辑入口显示「功能未开启」而不是消失**。公告文本显示在墙面贴图上要**自动换行并限制行数**，超长截断加「…」。无公告「今天还没有公告」。
6. **访客登记摘要**（前台一角）：读 `GET /foyer` 的 `visitors`，只显示 `lan` 和 `wall` 两类的总次数与最近时间（`lastAt` 用金边时间的相对表述，如「3 小时前」）；`enabled:false` 或无记录显示「尚无访客记录」；**界面文案不使用「设备数」这个说法**（只说「访问次数」；董事会尚未确认设备口径）；**本任务不做任何「逐设备」展示**（`/foyer/visitors` 仅本机接口，留给以后）。
7. **等候区人物 —— 本任务只做「数据与面板」，不让人物走过去（已拆到 S1-5b）**：Codex 核查发现 S1-4b 的 `visitConsumer` 规则（有 `waits` 的人不能开始访问、出现等待就召回）与「有待回答事项的人走去等候区」直接冲突，需要先补 `foyer-paths.js` / `director.js` / `office-layout.js`，那是 **S1-5b** 的工作（`S1-5b-waiting-people.md`）。**本任务**只做：① `foyer-panels.js` 里的**纯函数** `selectWaitingPeople(waiting, seats)`（只取真实 `kind==='question'` 且有 `agentId` 的条目，同一人去重，按座位数封顶，座位数参数由调用方传入，**默认 4**，**不要**去猜沙发容量也**不要**改 `office-layout.js`）并配好测试，供 S1-5b 使用；② 前厅服务台旁的「等候」面板只显示**数量文字**（例如「等候中 N 人」/ 空态「当前没有待处理事项」）；③ **不得有任何人物因为等待状态走向等候区**，**不改 `director.js` / `foyer-paths.js` / `office-layout.js`**。现有的「有人在等你」气泡 / 画面保持不变。
8. **交办箱**（`foyer-panel-handoff`）：这是 T17 对话功能的入口——**本机**点击后打开「选同事 → 对话 → 选消息 → 转任务」的现有流程（复用 `chat-panel.js` 与 `chat_to_task`，**不新增直建任务的后门**，沿用 T17 的扫描、额度和确认）；局域网 / 大屏**隐藏入口**；对话功能总开关（`chat.json`）关闭时，入口显示「对话功能未开启」；无选中消息时提示「先与同事对话，再把选中的内容交给 Lead」。
9. **面板性能**：这些面板的贴图是 `userData.dynamic = true` 的 Canvas 贴图；**只在数据变化时重绘**（比较数据签名），不要每帧重绘；每块面板贴图 ≤ 1024×512；重绘失败不影响主渲染（try/catch，面板保持上一帧）；页面隐藏时不轮询里程碑和 `/foyer`（出勤等随 `/state` 的数据本来就由现有轮询提供，**不新增 `/state` 轮询**）。
10. **新增轮询**只有两个：`GET /foyer`（30 秒）和 `/wall/data.milestones`（30 秒）；两者失败都显示空态文案并在控制台只打一次警告，不要重复刷屏；不得在 `/state` 的 3 秒轮询里附带新请求。
