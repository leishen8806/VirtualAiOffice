## 要规划的内容
1. **现状对照表**：治理中心目前已经能看什么（审批、委员会、晨会、验收、返工、交接、记忆、契约视图、调度建议、工作量等）、对应的数据来源（`/state` 字段、`/governance`、`/contract-view`、`/scheduler/suggest`、事件账本、activity），**新增指挥视图真正缺的是什么**——不要重复造已有面板。
2. **统一只读数据契约**（`CommandViewData`，JSON，**版本化**）：`{ schemaVersion, generatedAt, dataAgeMs, mode:'live'|'replay'|'demo', company, scope:{project?, range}, summary, queue, relations, execution, timeline, quality }`。逐字段给出：来源、口径、**未知值如何表示（`null` + 原因码，不得用 0）**、脱敏规则（**不含任务正文 / 评论正文 / 密钥 / 内部地址**；标题按现有展示策略截断）、更新频率与缓存（**不得增加对 Paperclip 的请求频率，复用 `/state` 与 L3c-fix 的懒取数 + 60 秒缓存做法**）。
3. **阶段映射**：展示阶段「需求确认 → 已领取 → 执行中 → 验证中 → 待验收 → 已验收」**映射到现有 Paperclip 状态与已有证据**，**不得修改 Paperclip 状态机**；对每一阶段写明**当前能否可靠判断**（依据 L0-A4：`activity` 没有状态转移字段、没有独立的验证 / 验收事件 → 「验证中 / 已验收」目前只能由 `done-rules` 的证据等级推断，且**默认未接线**）。**不可靠的阶段在第一版只显示「待验证（无证据）」，不得推断。** 进度只用「验收项通过 n / m」或「当前阶段 + 等待原因」，**不得用运行时长换算百分比，不得把 Agent 的「完成」显示为「已验收」**。
4. **三类关系分开**：组织关系 / 任务依赖（`blockedBy`，来自任务详情，见 L3c）/ 实际运行调用（`activity` 的 `runId`、事件类型）；每类的数据来源、可信度、默认是否显示（默认聚焦当前项目或选中任务，**不随机连线**）。
5. **「今日督办焦点」= 可处理的阻塞队列**：按阻塞类型（等待授权 / 依赖未完成 / 预算限制 / 验证失败 / 执行器异常 / 已交付待验收）给出**应指向的下一位处理人**与**可用的现有治理入口**；提醒规则（去重、冷却、处理后停止、升级对象）由**确定性规则**产生，**不调模型**；**不新增「强制完成 / 自动批准 / 一键重做」按钮**，需要处理时跳转现有治理入口。
6. **数据质量上屏**：成本卡 = 「已确认成本 | 未返回用量的执行数 | 最后更新时间」（真实数据：用量缺失 115 / 633，**未知不得当 0**）；断线 / 过期显示「更新中断」，**动画不得制造实时假象**；公司切换后**清空上一公司数据**。
7. **三种数据模式**：`live`（授权范围内真实数据，标新鲜度）、`replay`（已保存事件历史展示，不重放业务命令、不触发 Agent）、`demo`（**合成或脱敏素材**，无生产凭据、无业务写入；**默认应为 demo 或空状态，不得默认带真实任务 / 客户名**）。第一版建议只做 `live` + `demo`，`replay` 列为后续。
8. **UI 规格（不写代码）**：布局「顶部总览 / 左任务队列 / 中协作关系 / 右执行详情 / 下事件时间线」；**浅色（纸质）与深色（科技）两套主题，布局与状态颜色语义一致**，禁止密集闪烁粒子；**3D 小镇里只放一块「指挥中心屏幕摘要」，点击打开二维面板**，不在 3D 里读小字，不为此启动第二套高频轮询；移动端 / 390 px 的取舍。
9. **隔离与验收**：沿用小镇线 / 主线隔离契约（零 token、不写 Paperclip、默认关闭的独立开关、故障自降级、关闭时既有路由与页面逐字节不变）；列出**可测试的验收清单**：同一任务在各视图一致；没有证据不显示「已验收」；断线不假装实时；未知成本不变零；切换公司不串数据；关闭大屏不影响原业务；`/state` 耗时不因它增加（**以 L3c 事故为鉴：逐任务取数必须懒加载并缓存**）。
10. **分期卡草案**：拆成**每张约 1 小时**的卡（数据契约纯函数 → 只读路由 → 治理中心面板（`ui.js`，**必须浏览器验证**）→ 双主题 → 3D 摘要屏（Codex，经注册口或独立钩子，**注意 `app.js` 互斥**）→ 演示数据 / 回放），每张写：谁做、改哪些文件、前置、验收要点。**第一版范围：选一个现有项目，把一项真实任务的「创建 → 领取 → 执行 → （验证）→ 返工 → 验收」经历完整展示，仅只读 + 跳转。**

## 检查脚本 `docs\command-view-checks.mjs`
对 `command-view-sample.json` 做自动检查：版本字段、`null` 代表未知（**任何地方出现把未知写成 0 的成本字段即失败**）、阶段值只在允许集合内、**不含 `title / description / body` 之外的敏感键与长文本**（标题长度上限）、`mode:'demo'` 时不含任何真实标识模式、数据过期标记存在；带 `COMMAND_VIEW_CHECK_MUTATE=zerocost | fakeaccepted | leak | stale` 四个故意破坏开关，**各让检查失败一次**（贴输出）。
