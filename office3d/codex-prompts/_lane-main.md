# 主线共用规则（所有「主线」任务都隐含包含本页；先读 `_common.md`，再读本页）

> 董事会 2026-10-21：主线 = 自主团队与主流程优化（任务契约、证据驱动完成、程序化调度、治理增强、多租户 / 认证）。**自发管理的正式定义见知识库 `项目\现状盘点与融合策略.md` 第八节；补充契约见第九节。**

## 一、任务粒度与交付方式
- **每个任务约 1 小时**；做不完就停在可验证的最小子集，如实汇报。
- **完成 = `node --test tests/*.test.mjs` 全过（当前 574 项起，不得放宽已有断言）**；汇报「做到 / 没做到 / 未验证」且**与磁盘一致**。开工前备份到 `office3d-backup-<任务名>\`。

## 二、主线设计原则（每个任务都要遵守）
1. **复用 Paperclip 原生机制，不建第二套**：任务所有权 / 领取 / 执行锁 / 阻塞依赖 / 预算 / 审批以 Paperclip 为准；办公室 3D 只做它没有的治理增强与可视化。
2. **「Helix 提议，程序校验」**：是否允许执行由**确定性规则**判断（依赖、权限、预算、状态），不交给提示词。
3. **执行结束 ≠ 验证通过 ≠ 验收完成 ≠ 已合并 ≠ 已上线**；证据绑定产出版本，产出变化后旧验收失效。
4. **事件触发而非定时扫描**；**重试前先核对副作用**；不重复领取；过期结果不得覆盖新结果。
5. **新功能默认关闭**，独立 JSON 开关（缺失 / 损坏 / 非布尔 `true` 视为关闭）；**关闭时既有所有路由逐字节不变**（`tools\tenancy-snapshot.mjs` 快照对比，**开工第一步先对运行中的旧服务拍快照**）。
6. **纯函数核心 + 薄接线**：规则放纯模块（不引用 `fetch / Date.now / Math.random`，时钟与数据由调用方注入），`server.mjs` 只做薄接线；**同一时间只有一个任务改 `server.mjs`，主线优先**。
7. **对 Paperclip 默认只读（GET）**；任何写操作必须是任务卡明确允许、默认关闭、可审计、可撤销的；**不创建 / 修改公司、同事、预算、审批**。
8. **不读取、打印、写出任何密钥 / 令牌 / 口令 / 访问码**（`lan.json`、`wall.json`、`telegram*`、`*.dpapi`、`config.json` 里的密钥字段）；来自 Paperclip 的文本当不可信输入（去控制字符、截断、不进日志正文）。
9. **外部系统对接预留**：事件格式对齐 `E:\VirtualAIOffice\repo-3d\docs\architecture\event-contract.md`（版本化信封），**不另造一套**；租户与权限设计按「以后可与别的系统对接」来写，**但本阶段不开发 IM / OA / DAEN 对接**。

## 三、热点文件
`server.mjs`（同时只有一个任务改，主线优先）；`app.js` / `director.js` / `office-layout.js` 是小镇线所有，**主线任务不要改**；治理模块（`committee / standup / acceptance / rework / handoff / chat / memory / workload / stats / evidence-version / events-ledger / governance`）与 `tenancy\` 属主线。

## 四、服务运行方式
办公室服务与上班调度由 **pm2** 托管；**不要自己启动第二个 `node server.mjs`，不要自己重启服务**——需要重启时汇报里写明，由董事会侧 `pm2 restart office3d`。
