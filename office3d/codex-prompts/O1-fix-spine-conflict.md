## 缺陷 1（必须修）：「东侧入口脊柱」被 Dr.life+ 工作室切断
- 第 8 节写「东侧入口脊柱 `x=0…4, z=-4…15`，净宽 4 m，继续连接入口中轴 `x=2`」，但第 4.1 节 `drlife` 外框为 `x=-5…13, z=4…10`，**与脊柱重叠 `x=0…4, z=4…10`**。我用独立脚本验证：`OVERLAP drlife x spine`。
- 后果：入口 → 前台 → 北侧走廊的主轴被房间挡住；当前脚本之所以仍 `PASS`，是因为可达性检查找到了绕行（前厅西横廊 → 吧台西侧 → 南走廊），**但这与「中轴前台 + 入口脊柱」的设计意图相反**，且会把所有访客与同事都引到西侧。
- **要求**：在推荐方案里解决，并说明取舍。可选做法（你选一个并写明理由，或提出更好的）：① 把 `drlife` 缩成 `x=5…13`（或拆成脊柱两侧各一块，不跨脊柱）；② 把脊柱缩为只在 `z=10…15`（前厅）存在，并在 `drlife` 门前另设「脊柱延伸」走道；③ 把 Dr.life+ 工位 8 个重新排到不压脊柱的位置。**工位总数 25、各人到区域的映射、`drlife` id 都不变；`drlife` 面积不得小于现有 Dr.life+ 房间面积的 80%。**

## 缺陷 2：检查脚本没有「走廊 / 脊柱不得与房间重叠」的通用检查
- **要求**：新增检查 `declared corridors and spine do not overlap any region`（对所有已声明走廊、环路、脊柱 × 全部区域外框做相交检测，边界接触不算重叠）；`OFFICE_REDESIGN_CHECK_MUTATE=spine` 开关把脊柱改成压住某房间，**必须让该检查失败**（贴输出）。同时检查吧台包围圆与南 / 北主走廊的相交（O1 里吧台下沿 `z≈2.5`、上沿 `z≈-4.5` 与走廊 `z=2…4` / `-6…-4` 有约 0.5 m 相交；若是有意的「走廊穿过环路」，**在文档里写明并让检查按「允许相交的白名单」处理，不要静默放过**）。

## 遗漏 3：中央南北两块空白没有说明用途

- **要求**：说明这两块空白的用途（例如：北 = 开放式协作区 / 绿植景观带；南 = 前厅西侧缓冲），或调整外框、区域让空间被利用；说明圆心为何取 `z=-1`（或改为 0 并同步全部坐标与检查）。
