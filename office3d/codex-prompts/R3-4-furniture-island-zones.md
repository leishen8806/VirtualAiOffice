## 分工与要做的事
**A. Trae（先做，模块 + 预览页；配色读 `office-theme-v2.js` 令牌，不 import `dr-campus-*`）**
1. **吧岛模块 `office-island.js`**（取代 `office-bar.js` 在 `?layout=3` 下的使用；`office-bar.js` 在 `?layout=2` 下保持不变）：按 `LAYOUT_V3.island` 的 Ø12 分解——圆形木质吧台（外径与高度按 R3-1）、**中央一棵大型景观树（程序化树冠与树干，高档 / 低档两套）**、**吧台下沿暖色 LED 灯带（自发光，不新增光源）**、外圈吧凳、东西沙发弧（**蓝灰 / 青灰织物配色**，参考图）、与 4 m 环形通道的关系；**材质口沿用 O6b 的 `materialOverrides` + 世界坐标 UV 口**；碰撞段按 `LAYOUT_V3.island`（环通道净宽 ≥ 4 m）。预算：吧岛模块高档 ≤ +5 calls、低档 +2（预览页读数）。
1c. **工位显示器（董事会 2026-10-22 反馈：屏幕「脱落」）：** 工位显示器做成**共用函数**，屏幕平面的位置 / 朝向 / 倾角 / 尺寸**一律从显示器模型的屏幕玻璃面实测得到**（方法见 `O4c-monitor-fit.md`），不再手填常数；验收必须有工位近景（多位置、多朝向，斜上方与侧面）。
1a. **沙发 / 座位与坐姿对齐（董事会 2026-10-22 反馈：人坐沙发时髋部陷进座面、小腿穿过前立面）：** 吧岛沙发、吧凳、会议椅等**所有真人 / 展示人物会坐的座位**，座面高度、座深、腿部空间必须按 `people.js` 里真实「坐椅」动作的实测数据（见 `O6c-lounge-seat-fit.md` 的 `LOUNGE_SIT`：`hipY / kneeZ / footZ`）设计，**座位数据带 `sitOffset: { forward, lift }`**；验收必须有「坐着的真人」3 角度截图（髋部在座面上、小腿在前方自然下垂、脚踩地面、不穿模）。
1b. **吧凳可坐（O6O7 遗留）：** rev2 的 10 个可视吧凳只是装饰席（布局的 coffee seat 与 Trae 的吧凳不是同一套坐标，真人用的是 6 个沙发休息点）。`LAYOUT_V3.island` 里**吧凳坐标、椅高、朝向只定义一套**，并导出给路径（R3-5 的吧岛咖啡互动）与人物坐姿绑定使用；展示人物可在吧凳停留（标注模拟），真人是否坐吧凳由 R3-5 决定。预算口径见 R3-4 末尾的「calls 口径」。
2. **功能区家具模块：** `休闲展示区 8×6`（低矮展台 + 沙发 + 展示墙面）、`创意讨论区`（圆桌 / 白板墙 / 便签墙，沙发椅）、`餐饮休憩角`（吧台小岛 / 高脚凳 / 圆形小桌）；每个一个工厂函数，签名沿用注册口的 `factory({ THREE, root, layout, materials, collision, canvasTex, low })`；**没有任何可点击的「同事」，不增加真实席位**；标牌文字用 `canvasTex` 的真实契约 `(ctx, w, h)`（我们踩过这个坑，测试里用忠实模拟宿主签名的替身）。
3. **预览页** `office-island-preview.html`（吧岛）与 `office-zones-preview.html`（三类功能区），深浅主题，显示 calls / 三角形，只请求静态资源。

**calls 口径（2026-10-22 裁定，适用于所有 R3 卡与 AS2 卡）：** 卡里写的「模块 ≤ N calls」指**模块自报的批次数（预览页读数）**；主场景高档的 `env.js` 会把 `RenderPass` 与 `GTAOPass` 法线阶段各画一遍，所以**主场景实测增量约为模块自报的 2 倍**（O6O7 实测：吧台自报 3 → 主场景 +6；展示人物自报 2 → +4）。验收时同时写两个数：模块自报值（对照卡里的 N）与主场景增量（应 ≈ 2N，并确认 `?layout=3` 总帧 calls 仍低于默认页面）。
