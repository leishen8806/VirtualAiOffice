# T11-daily-replay：今日精彩回放（真实事件账本 + 一键回放）

先读 `_common.md`。**本任务的例外规则：** 允许新增 `events-ledger.mjs`、`replay.js`、`tests/events-ledger.test.mjs`、`tests/replay.test.mjs`；允许修改 `server.mjs`（**只限第 5 节接线**，不要碰局域网访问码、`hostOk`、大屏令牌、`act()` 已有分支、静态文件白名单；`buildEvents` 的现有逻辑和输出**不得改动**，只在它外面接账本）、`app.js` 与 `ui.js` 与 `index.html`（**只限**回放入口、回放控制条、回放模式下暂停接收实时事件所需的最小挂钩，其余逻辑放进 `replay.js`）、`README.md`。**不要改** 其它 `*.mjs` 业务模块、坐标 / 座位 / 房间、渲染材质与光源。**不得向 Paperclip 发任何写请求**。不新增依赖、不新增 3D 模型和纹理（回放只复用现有人物动作、气泡和 `director.enqueue`）。**本任务和 T10（低配优化）都会碰 `app.js`，不要与 T10 同时进行；如果 T10 未完成，把对 `app.js` 的改动压到最小并在汇报里列出每处。** 备份到 `office3d-backup-replay`（办公室目录没有 Git）。

【背景】董事会想让领导「一键看今天办公室里发生了什么」。现有 `/state.events` 是 `buildEvents()` 从 Paperclip 活动流（最近约 500 条）实时整理出的短列表（本次实测只有 40 条，类型 `speak` / `celebrate` / `report` / `dispatch`，字段 `id, at, kind, from, to, ref, text`），**不保存历史**：服务重启或事件滚出窗口后就没了。要做回放，必须先有一本**真实事件账本**。硬规则：**动画只来自真实事件；没有记录的时段就明说没有记录，不补演、不编造、不用随机对话填充。**

## 1. 事件账本（`events-ledger.mjs`）
- 订阅现有 `state()` 里已经生成的 `events`（不重新解析活动流，不改 `buildEvents`），按 `id` 去重追加到 `events/YYYY-MM-DD.jsonl`（金边日期，目录不存在则建；每行一个 JSON；**原子追加**，崩溃不损坏已有行）。每条只存 `id, at, kind, from, to, ref, text`（`from/to` 是 agent id，存原样，回放时再映射成名字）。
- **存入前脱敏**：`text` 走 `wall.mjs` 的 `redactText`（金额、IP、邮箱、链接、疑似密钥打码；复用，不要另写）。
- 保留 30 天（启动时和每天一次清理超期文件）；单日文件超过 5000 条时当天停止追加并在 `/state` 提示（防止异常刷屏撑爆）。
- 启动时读取今天的文件建立 `id` 集合；损坏的行跳过并计数，不崩溃。`enabled:false`（`events-ledger.json`，**默认开启**）时不写。
- 账本的第一条事件时间即「回放可用起点」，页面要写明「回放自 yyyy-mm-dd hh:mm 起有记录」；之前的日子不可回放（**不要用 Paperclip 活动流倒推补录**）。
- 绝不记录评论正文、任务描述、令牌、访问码、金额明细；`text` 本来就只是 `buildEvents` 产生的短句，若发现含更长内容，截断到 120 字。

## 2. 回放数据接口
- 新增只读 `GET /replay?date=YYYY-MM-DD`（缺省为今天）：返回 `{date, from, to, available, events:[{at, kind, from:{id,name}, to:{id,name}|null, ref, text}], gaps:[{from,to}], counts:{dispatch, report, celebrate, speak}, firstRecordAt}`；`gaps` 是相邻事件间隔 > 30 分钟且处于上班时段的空档（只标出，不补）。放在现有访问控制之后：本机和局域网（已过访问码）可用；**大屏令牌设备不得访问**（沿用 `API_PATHS` 的做法）。日期格式非法返回 400，没有任何记录返回 `available:false` 和空数组，不是错误。
- 返回前对 `text` 再走一遍 `redactText`（防止账本里有旧版本写入的内容）。

## 3. 回放模式（前端，`replay.js` + 最小挂钩）
- 入口：「查看」组里加「▶ 今日回放」（可选日期：今天 / 昨天 / 账本里有记录的日子）。
- **时间压缩**：把上班时段内的事件按顺序播放，事件之间的空档压缩（单个空档最多显示 2 秒）；整日回放总长默认 ≤ 90 秒；事件太多（>300）时，`speak` 类按时间窗合并抽样、**但 `dispatch` / `report` / `celebrate` 一条都不丢**，并在控制条写明「已抽样显示 N / 共 M 条聊天」。
- **播放控制条**：播放 / 暂停、速度 1× / 2× / 4×、时间轴（可拖动跳转，按事件类型着色，空档用灰色并写「此时段没有记录」）、当前时刻、退出按钮；屏幕上始终有醒目的「回放 · yyyy-mm-dd」标识，**避免和实时画面混淆**。
- **播放方式**：逐条调用现有 `director.enqueue`（`dispatch` = 走到对方桌边交接、`report` = 汇报、`celebrate` = 完成庆祝、`speak` = 气泡），**复用现有动作和碰撞 / 避让**；回放中同事保持各自工位出发，不得穿墙、不得叠人；回放时间点早于当前实际状态时，不要改变真实的工位占用逻辑（回放的人物是同一批模型的演出，退出后**必须回到实时状态的位置和朝向**）。
- **回放期间暂停接收实时事件**（排队，退出后正常处理，不丢）；休息区闲聊、八卦等装饰性自动演出在回放期间关闭，避免和回放混在一起。
- 结束画面：只显示由账本**统计出来的数字**（派单 N、交付 N、庆祝 N、第一件和最后一件事的时间），不写任何生成的「总结文案」或评价。
- 键盘：空格暂停 / 继续，Esc 退出；窄屏可用；所有文字用 `esc()`。
- `?replay=YYYY-MM-DD` 可直接进入某天回放（本机 / 局域网用；大屏嵌入模式 `?wall=1` **不支持**，被忽略）。

## 4. 不做的事（写进汇报的「范围」里）
不补录历史、不用随机或生成的对话填充空档、不显示评论正文或任务描述、不回放别的日期的未脱敏数据、不增加任何 3D 资源、不修改审批 / 验收 / 派单的任何逻辑、不向 Paperclip 写任何东西。

## 5. 接线（`server.mjs`，只允许这些）
1. `import { createEventsLedger } from './events-ledger.mjs'`，在 `state()` 产出 `events` 之后调用 `ledger.ingest(out.events)`（**不改变 `/state` 里 `events` 的内容和顺序**）；创建时传入 `redactText`（来自 `wall.mjs`）、`dir`、`now`、`names`（agent id → 显示名，用现有 `names`）。
2. 新增 `GET /replay`（第 2 节）。
3. `/state` 里加 `ledger: ledger.view()`（今日条数、回放可用起点、跳过的损坏行数、是否因超限停写）。
4. 无 `act()` 改动。
5. 重启后第一次写入不依赖 Paperclip；账本模块自身出错只记日志，**不得影响 `/state` 的返回**。
