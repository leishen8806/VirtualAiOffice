## 背景（董事会已定，见知识库第十九节）
多家**真实公司**（在 Paperclip 里新建的公司，各自 company id 与老板）入驻小镇；**别家老板通过局域网自己管理自己的公司**；经济采用**方案 A**（公司账户 + 追加式账本）；所有公司共用 DR 币；**充值的目的是让入驻公司自己承担真实算力成本**（算力钱包）；同事跨公司见面先做表演式（零 token）；先做**不涉及资金的地基**。**现状：** `server.mjs` 里 `COMPANY` 是写死的一个常量；访问模型是「本机完全权限、局域网只读（访问码）、大屏令牌最小权限」，没有账号 / 角色 / 多用户写权限。KhmerX、Dr.life+ 目前是智序工场公司下的**项目**，不是独立公司。

## 要交付的内容（全部写进 `m5-0-design.md`，每个结论要有依据：代码位置 / 脚本输出 / 明确的假设）
**1. 现状体检（只读）。** 逐项列出现有访问控制的**全部入口**（HTTP 路由、静态文件、`/act` 动作、cookie、令牌、`Host` 校验）及其权限层级，画成**权限矩阵**（本机 / 局域网已登录 / 局域网未登录 / 大屏令牌 × 读 / 写）；找出**所有隐含的单公司假设**：`grep` 出 `COMPANY`、`company-id.txt`、写死的项目 id 文件（`*-project-id.txt`）、各 JSON 状态文件（`rework.json` / `chat.json` / `memory.json` / `foyer.json` / `workhours` / `roadmap.json` …）、知识库路径、记忆库路径、`pc.py` 的假设，给出清单：**每一项归类为「按公司隔离 / 全局共享 / 仅智序工场」**并写出迁移方式。
**2. Paperclip 多公司能力核实（只读 GET）。** 用只读脚本 `scripts\probe-paperclip.mjs` 核实并记录：`GET /api/companies` 的字段（含 `budgetMonthlyCents` / `spentMonthlyCents` 的含义与是否可强制执行——**只读推断，不得修改**）；公司之间的**数据隔离边界**（用一个公司的 id 请求另一个公司的任务 / 同事 / 运行会怎样——**只在只读 GET 且只对已有的公司 id 进行；现在只有一家公司时，写明「无法实测，需要第二家公司才能验证」，不要自己创建公司**）；运行记录的 `usageJson` 字段形状与完整性（`inputTokens / outputTokens / cachedInputTokens / model / billingType / costStatus / usageSource`）、缺失率、`per_run` 与累计的关系；同事的暂停 / 恢复在 API 上的形态（**只读文档 / 响应形状，不调用**）。**列出所有无法验证的点和需要第二家公司才能做的验证清单。**
**3. 威胁模型（`threat-model.md`）。** 资产（各公司的任务 / 知识库 / 记忆库 / 工作量 / 访客记录 / 公司账户与算力钱包 / 账本 / 账号口令 / 会话）；攻击者画像（**别家老板（恶意或失误）**、同一局域网内的未授权设备、入驻公司的同事（AI）被诱导、模拟公司、智序工场内部）；逐条 STRIDE，至少覆盖：**越权读 / 写别家公司数据（水平越权）、普通成员越权成老板（垂直越权）、会话劫持 / 固定 / CSRF、口令爆破与撞库、枚举公司 / 用户、通过静态文件 / 导出 / 日志 / 错误信息泄漏、通过 `/act` 的 `_` 前缀透传、跨公司「信箱」注入（提示词注入）、算力钱包被刷（刷充值 / 刷用量 / 重放）、账本篡改、时间与幂等、审计日志被删改、拒绝服务（大量请求耗尽本机）、老板把本机变成跳板访问内网**。每条给：风险等级、缓解设计、验收方法。
**4. 身份与访问设计。** 账号模型（公司老板 / 公司成员 / 公司只读 / 平台管理员=智序工场董事会）；**口令只存加盐慢哈希**（用 Node 内置 `crypto.scrypt`，**无新依赖**；给出参数、盐、常量时间比较、迁移与重置流程，**不得设计明文或可逆存储**）；会话（随机不可预测 id、服务端存哈希、绝对 / 空闲超时、登出即失效、**每家公司独立 cookie 名与作用域**、`HttpOnly; SameSite=Strict`，局域网是 http 所以不加 `Secure` 但要说明风险与替代）；登录限速与锁定（按账号 + 按来源，退避，不泄露账号是否存在）；**CSRF 方案**（`/act` 目前靠令牌，多用户后怎么办）；**每个请求必带「公司上下文」且由服务端从会话推导、绝不信任客户端传来的 company id**；跨公司访问一律 403 且**不泄露对方是否存在**；平台管理员的权限边界与「代入」审计；**默认关闭 + 首次开启由董事会确认**（和现有新功能一致）。给出**新的权限矩阵**（角色 × 资源 × 读 / 写）与路由表。
**5. 数据模型与目录结构。** 公司注册表 `companies.json`（字段、状态机：申请 / 审批 / 活跃 / 暂停 / 退出）；**每公司独立的数据目录**（给出完整目录树：状态文件、账号、审计、账本分区、知识库、记忆库…）与路径穿越防护（公司 id 的字符集与长度限制、`path.resolve` 后必须仍在目录内）；**账本如何按公司分区又保持一本追加式哈希链**（或每公司一条链 + 全局汇总链，二选一并论证，保持 T20 的幂等与守恒不变量）；Paperclip 公司 id 与小镇公司 id 的映射；把「现有单公司」迁移成「公司 #1」的**零行为变化迁移方案**（含回滚）。
**6. 审计日志设计。** 哪些操作必记（登录 / 登出 / 失败 / 锁定、所有写操作、权限拒绝、跨公司访问尝试、充值、价目变更、暂停 / 恢复同事、平台管理员代入）；字段（时间、公司、用户、来源地址摘要、动作、对象、结果、请求摘要，**不含口令 / 令牌 / 正文敏感内容**）；**追加式 + 哈希链 + 按月滚动**；谁能读（老板读自己公司的，平台管理员读全部）；保留期；防篡改的可检验方法（提供校验脚本草案）。
**7. 算力计量与算力钱包方案（对应知识库第十九节「十九（补）」）。** 在第 2 节核实的字段基础上设计：计量口径（非缓存输入 / 缓存输入 / 输出 / 模型系数；`unpriced` 时我们自己定价；跨天与跨月归属；重复读取 / 乱序 / 缺失的幂等处理，**用 `runId` 去重**）；价目表（版本化、生效时间、变更审批与审计）；**两个口袋**（算力钱包与运营资金）的账本科目与守恒方程扩展（充值 = mint 带收款记录 ID；算力消耗 = 永久回收）；余额告警（20%）、归零后的**暂停派活**机制（先说明可行的 Paperclip 机制有哪些，哪些**必须做第二家公司实测**才能确定）、**单公司每小时用量上限**、失控运行的处理；计量任务本身**不得消耗 token**（只读 GET，间隔与开销估算）；老板侧页面需要看到的数据与**隐私边界**（只看自己的）；充值流程的**数据合同**（线下收款记录 ID、金额、操作者、幂等键、月上限与余额上限；**系统不接任何支付接口、不收集银行卡 / 账户信息**）。
**8. 小镇层的多公司映射（不实现，只写合同）。** 公司名片、商业地块、公司账户、**模拟公司**（必须标注「模拟」、只与金库闭环、不持有可提取资金）、表演式见面与交易的数据来源与**零 token 约束**（知识库第十八节）；明确**哪些数据可以跨公司可见**（公开名片、公开地图位置）、哪些绝对不可以。
**9. 分阶段实施拆分（M5-1 …）。** 6–10 个互不冲突的小任务：每个写目标、允许改 / 不得改的文件、依赖、验收要点、风险、建议执行者；标出可并行与必须串行；**哪些必须先有第二家 Paperclip 公司才能验收**；并给出「**在没有任何多用户功能被开启时，现有系统行为零变化**」的验证办法。
**10. 红队检查清单与验证脚本。** `scripts\` 里提供**只读的自检脚本草案**（针对现有代码的静态检查：是否存在不经 `company` 上下文的全局状态读写、路径拼接是否可穿越等），并写出 M5-1 之后每个阶段必须执行的**越权测试用例清单**（至少 40 条，每条含前置、请求、期望的 HTTP 状态与响应内容）。
**11. 风险与未决项。** 你发现但不能自己决定的事，每条给推荐选项（例如：入驻公司的同事是否运行在同一台机器 / 同一份 Paperclip；是否需要进程级或操作系统账户级隔离；局域网明文 http 下口令传输的风险与可接受的替代；老板忘记口令的重置由谁负责；单家公司的同事数量上限；模型额度的实际来源与上限）。
