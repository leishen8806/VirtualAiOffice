【背景】验收证据块（`E:\VirtualAIOffice\knowledge\流程\模板\验收证据.md`）第一行是 `【验收证据】对象版本：<Git 提交号 | 无 Git：逐个文件写 SHA-256>`，规矩写着「版本不一致（验证之后又改过）→ 这一项证据作废，重新验证」。**但没有任何程序核对**：同事验证完又改了东西，董事会 / 超时验收委员会看到的仍是旧证据。本任务让程序在**验收的那一刻**把证据里的版本和**当前实际版本**做核对，把结果摆在验收人面前，并挡住「版本已变」的任务被自动验收。**只做只读核对，不替任何人做决定。**

## 1. 机器可读的版本写法（Claude 会写进模板和同事规则，你按这个解析；解析必须同时容忍旧写法，旧写法一律判「无法核对」，不得报错）
证据块首行 `【验收证据】对象版本：` 之后，用分号分隔一个或多个条目：
- `git:<仓库绝对路径>@<提交号>`（提交号 7–40 位十六进制）；
- `sha256:<文件绝对路径>=<64 位十六进制>`（可多个，用分号分隔）。
全角 / 半角冒号、分号、等号容忍；Windows 路径的反斜杠和正斜杠都要处理。

## 2. 核对（`evidence-version.mjs`，纯函数 + 受限的文件 / git 读取）
- 取任务里**最近一条含 `【验收证据】` 的 agent 评论**的写入时间和版本条目。
- **git 条目**：当前版本 = 该仓库**当前检出分支的 HEAD**（`git -C <repo> rev-parse HEAD`）。结果：`一致`（HEAD 以证据提交号开头）/ `已变`（HEAD 不同：再用 `git -C <repo> rev-list --count <证据提交>..HEAD` 和 `git diff --name-only <证据提交> HEAD`（**只取文件名，最多列 20 个，不读内容**）给出「之后新增 N 个提交、改了哪些文件」；如果证据提交不是祖先，写「证据提交已不在当前历史中」）/ `无法核对`（仓库不存在、不是 git 仓库、命令失败，写原因）。有**未提交的改动**（`git status --porcelain` 非空）时另标「工作区有未提交改动」，只给数量，不给内容。
- **sha256 条目**：对每个文件重新计算哈希并比较：`一致` / `已变`（列出哪些文件哈希不同）/ `缺失`（文件不存在）/ `无法核对`。
- 汇总：全部条目一致才算 `版本一致`；任一条目已变 / 缺失 → `版本已变`；证据缺版本或写法不可解析 → `证据缺版本（无法核对）`；其余 → `无法核对（原因）`。
- **安全边界（硬规则）**：
  - 只允许读取白名单根目录内的路径（默认 `E:\VirtualAIOffice`、`E:\Dr.life+`、`E:\KhmerX`、`E:\pc-worktrees` 或 `E:\VirtualAIOffice\pc-worktrees`，以现有任务里真实使用的路径为准，写进 `evidence-version.json` 的 `roots`，可由董事会调整）；路径规范化后必须在白名单内（防 `..`、符号链接逃逸、大小写和盘符技巧），否则 `无法核对（路径不在允许范围）`。
  - **禁止读取或哈希**以下文件，即使在白名单内：`lan.json`、`wall.json`、`telegram*`、`*.dpapi`、`.env*`、`*ed25519*`、`*.pem`、`*.key`、`config.json`（任何目录）。命中直接 `无法核对（受保护文件）`，且**不得把这些路径写进日志**。
  - 只用 `execFile('git', [...固定参数])`，**不经过 shell**；仓库路径和提交号严格校验（提交号只许十六进制）；加 `-c core.fsmonitor=false -c core.hooksPath=NUL`；每条命令 5 秒超时；单个文件哈希上限 50 MB，超出 `无法核对（文件过大）`；一次核对最多 10 个条目。
  - 不输出任何文件内容；`git diff` 只取文件名。输出走 `wall.mjs` 的 `redactText`。
- 结果按「任务更新时间 + 证据评论 id」缓存；git HEAD 每次核对现取（不缓存超过 60 秒）。
