# T7-office-layout-square：重新规划区块，让办公室布局更方正合理

先读 `_common.md`。**本任务的例外规则：** 这是一次跨多个文件的布局重构，允许修改 `office-layout.js`、`office-partitions.js`、`wing.js`、`app.js`（布局、座位、地毯、家具、区域镜头、小地图范围、大屏镜头点位）、`director.js`（只限走道 / 门 / 路径常量的统一）、`landmarks.js`（仅在外围景观和新建筑边界冲突时）、`index.html`（只限小地图尺寸 / 样式如需调整）、`tests/office-layout.test.mjs` 等已有的布局和行人动线测试、`README.md`；允许新增 `office-layout-plan.md` 和新的布局测试。**不要改** `server.mjs`、任何 `*.mjs` 业务模块（standup / committee / acceptance / blocked / wall / health 等）、局域网和令牌相关代码。**不需要重启服务**（纯前端），验收时浏览器 Ctrl+F5。

【背景和问题】现在的办公室由 9 个玻璃房间组成（`office-layout.js` 的 `OFFICE_ROOMS`），但整体**不方正**：房间宽深各不相同（产品 14.8×7.6、工程 22.5×4.8 的细长条、质量 14.8×5.9、Dr.life+ 14.7×10.7、董事会 11.6×6.9、知识中心 7.8×7.6、运维 8.6×5.8、评审室 / 计划室 10×8），外沿和门洞互相错开，走道有一条竖向（x=4.5）和一条横向（z=2.45）但宽度不一，工程室像一条夹在中间的窄带把空间切碎，南侧前场大片空地没有用上，西翼三块像是后接上去的。截图里能看到：玻璃盒子错落、边线不对齐、动线绕。要把它规整成**有网格感的方正布局**。

当前关键坐标（以代码为准，先自己读 `office-layout.js`、`wing.js` 的 `ROOMS`、`app.js` 的 `ZONES` / `SEATS` / `BOSS` / `carpet(...)` 调用、`director.js` 顶部常量）：
- 总范围 x −44…22（含西翼 −44…−22）、z −13…13；入口在南侧中部（`office-partitions.js` 里「建筑南侧…保留 3.6 米开口」）。
- 走道常量散落在三处：`director.js` 的 `CORRIDOR_X=4.5`、`DOOR`，`office-layout.js` 里的 `4.5`、`2.45`、`-20.5`，`app.js` 的 `DOOR_X=11.7`。**要统一到 `office-layout.js` 一个来源。**
- 25 位同事的座位在 `app.js` 的 `SEATS`（产品 4 个、工程 6 个、质量 4 个、Dr.life+ 8 个、运维 2 个、知识库 1 个），苏晨的老板桌在董事会（`BOSS`），评审室 8 座、计划室 6 座。
- 依赖布局坐标的其他东西：`ZONES` 的镜头焦点、小地图范围 `MINI` 和房间矩形、大屏镜头点位 `WALL_SPOTS`、休息区 `LOUNGE_AREA` / `LOUNGE_SEATS`、`LIM` 镜头边界、`wing.js` 的日程墙和会议室屏幕、行人动线（`officeExit` / `officeTrip` / `corridorPath` / `loungeTrip`）。

## 目标（按重要性）
1. **方正、对齐、有模块**：房间尺寸取少数几种标准模块（比如宽 11 或 22 的整数倍、深 7.6 统一），房间外沿和门洞对齐到共同的网格线，所有坐标是 0.5 的整数倍；不再有窄带房间和错位的边。
2. **清晰的走道网格**：一条主横走道 + 一条主竖走道，宽度一致（建议 ≥3.2 米），所有门都开在走道上；动线短、不绕。
3. **按协作关系分组**：产品 / 工程 / 质量三个互相协作的团队相邻；运维和知识库放一起；评审室、计划室靠近团队区；董事会和 Dr.life+ 工作室各自成块；休息区和接待靠近入口。
4. **用上南侧前场**：把休息区、接待、入口形成一个像样的前厅，而不是一块空地。
5. **不增加渲染负担**：不新增外部素材，不显著增加网格数量（沿用 `mergeStatic` 的静态合并）；报告 `renderer.info.render.calls` 前后对比。

## 参考方案（可以改，但要说明为什么；不要照抄不动脑）
以 11 米为一列、7.6 米为房间深度：列边界 x = −44, −33, −22, −11, 0, 11, 22；北排房间 z −12.2…−4.6，主横走道 z −4.6…−1.4（宽 3.2），南排房间 z −1.4…6.2，南侧 z 6.2…13 为前厅（接待 + 休息区 + 入口）。北排自西向东：评审室、知识中心、产品与设计、工程（占两列，22 宽，6 座）、董事会；南排：计划室、运维、质量与安全、（中间两列留作开放协作区 / 休息区延伸）、Dr.life+（占两列，8 座）。座位间距、房间内的桌椅排列要同步重排，每个房间的座位都在房间内且面向合理方向。

## 阶段 A：先出规划（先不动场景）
写 `office-layout-plan.md`：① 网格定义和所有房间的新坐标表（x0 x1 z0 z1、门的位置和宽度）；② 一张 ASCII 平面图；③ 25 个座位 + 评审室 / 计划室座位 + 老板桌的新坐标表；④ 走道和门的连通关系；⑤ 新旧坐标对照；⑥ 你自己做的检查结果（房间互不重叠、最小走道宽度、每扇门都落在走道上、每个座位在自己房间内）。**规划里要解释取舍**，比如为什么这样分组。

## 阶段 B：实施
按规划改代码。`office-layout.js` 作为**唯一的坐标来源**，渲染、碰撞、动线、座位、小地图、镜头焦点、大屏点位都从它派生（能派生的不要再写死数字）。保持这些功能不退化：同事走到别人桌边、去休息区、去会议室、去董事会找苏晨；评审室投票会入座；晨会 / 验收的走位；点地面走过去；大屏的 `wallGo` 各个镜头；小地图点击跳转；搜索跳转到区域；老板桌和苏晨的访客站位。

## 验收（缺一不通过）
1. **测试**：`node --test tests/*.test.mjs` 全部通过，**不得为了通过而放宽或删除已有断言**（行人动线、布局、运动物理的测试都在守着这些规则；它们依赖具体坐标的地方，同步更新并说明改了什么）。新增布局不变量测试，至少：所有房间坐标是 0.5 的整数倍；房间两两不重叠；主走道最小宽度 ≥3.2；每个房间至少一扇门且门在走道一侧；每个座位在自己房间内；从入口走到任何房间的每个座位，`officeTrip` 的路径不穿墙；房间尺寸只出现少数几种标准规格。
2. **语法**：`node --input-type=module --check < 文件.js`（所有改过的浏览器模块；不要用 `node --check x.js`）。
3. **浏览器实测**（打开 `http://office.localhost:3200/`，改完 Ctrl+F5）：用「俯视」镜头在 1280×720 截改前 / 改后各一张平面图贴在汇报里；验证以下每一项并写出怎么验证的：25 位同事各就各位（座位 / 桌子 / 椅子对得上）；会议室、董事会、休息区、小地图、各区域镜头按钮、搜索跳转区域、大屏 `wallGo` 的每个 key 都落在正确位置；让几位同事走去休息区和会议室，看没有穿墙、没有卡在门口；控制台无报错。
4. 汇报里给 `renderer.info.render.calls` 和帧率的前后对比；有退化就如实写。真手机、真大屏上的观感无法验证的，写「未验证」。
5. 备份目录用 `office-layout-square`，先备份所有要改的文件；办公室目录没有 Git，覆盖了回不来。
6. **不要使用旧备份整份覆盖**：这些文件近期被多个任务改过（大屏嵌入模式、点地面走过去、小地图、老板桌、投票会走位、行人动线等），在当前版本上改。
