## 必须实现（对应 T8 第 8 节 1–10 条，逐条给「做到 / 没做到 + 原因」）
1. 提交端限额：每任务 ≤1 条（按 `source`）；每岗位每天 ≤3 条；每岗位待审同时 ≤5 条。超限的**移到 `已驳回/`**（这是已有的扫描拒收路径），原因类别「超限」；先到先得，晚到的被拒。
2. 默认有效期：未写 `expires` 时按类型补（project 180 天、process 365 天、personal 90 天），只在内存 / `memory.json` 里算，**不改条目文件**；过期不检索（现有 `expires` 判断要扩展到默认值）。
3. 用了续命、不用衰减：注入时在 `memory.json` 记 `lastUsed`、`hits`，有效期顺延到「注入日 + 默认期」；60 天没被注入过的标 `stale`：仍可检索但排序时排最后（不再加分），并进入月度清单。
4. 总量上限（有效条目）：personal 每岗位 30、project 200、process 80；超限**只提示**（`/state.memory` 和清单里），不删不移。
5. 归档目录 `记忆/归档/` 里的条目不进索引、不检索（现有目录白名单要确认不会把它当成正式库）。
6. 合并优先：相似度命中的条目（已有的重复检测）在 `/state` 和审核提醒里带「建议合并到 <路径>」。
7. 月度整理清单：每月 1 日（上班时间）或 `memory_monthly` 手动触发，生成 `记忆/整理清单-YYYY-MM.md`：过期 / stale / 超限 / 疑似重复 / 反馈「没用」累计的条目，**只写标题、路径、年龄、命中次数、原因类别，不含正文**；清单文件不进索引；已存在同月清单不覆盖（加 `-2` 后缀）；在 `reviewIssue` 已配置时提醒一次，未配置只在 `/state` 提示。
8. 度量：`/state.memory` 增加有效条目数（按类型）、归档数、本月新增 / 通过 / 驳回 / 归档、本月被注入次数、被注入过的条目占比、stale 数、超限提示。反馈：识别评论里 `【记忆库反馈】有用|没用 <路径>`（容忍全角括号 / 冒号），按路径累计 `useful`/`useless`；`useless≥3 且 useful=0` 进清单。**只读 Paperclip 评论，不写。**
9. 上界：检索结果仍 ≤3 条、评论 ≤1200 字（已有测试要继续过）；规模测试：在临时目录造 200 项目 + 80 流程 + 30×25 个人条目，给出索引重建耗时和一次检索耗时的实测数字，并写明可接受的理由。
10. `ui.js`「记忆库」一节显示上面的度量和超限 / stale 数，所有文字用 `esc()`；不显示条目正文。
