# O4c-monitor-fit：工位显示器「屏幕脱落」——实时屏幕平面与显示器模型对不齐（小卡，约 1 小时）

**执行者：Codex（会话一，办公区产线；`office-furniture-v2.js` 的持有者）。** **排在 H2b 之后、R3-1 之前。** **董事会 2026-10-22 反馈（截图）：全部电脑屏幕像是「脱落」了，细节处理不到位。** 截图里暗色屏幕画面与米白色显示器外壳不重合，像一块屏幕浮在显示器前面。

先读：`_common.md`、`office-furniture-v2.js` 第 78–101 行（`screen(...)` 与工位循环）、`assets3d.js` 的 `placeFurniture` 与 `computerScreen` 资源（Kenney Furniture Kit 的显示器模型）、`office-layout-v2-scene.js`（只读）。

## 根因（我读代码得出，请你用实测确认）
每个工位有两层：① 显示器模型 `asset('computerScreen', seat.x, seat.z - .17, .66, .46, .16, .76)`（包围盒 0.66 × 0.46 × 0.16，立在桌面 `y=.76`）；② 另一块独立的实时屏幕平面 `screen(seat.x, 1.065, seat.z - .075, .55, .31)`——位置、大小都是**手填的常数**，**没有任何旋转（`yaw = 0`，也没有俯仰倾角）**，且离显示器模型正面有固定偏移。显示器模型本身的屏幕面是有倾角的（我在截图里看到屏幕向后仰），所以平面与模型屏幕面既不平行、也不贴合：平面显得「飘」在外壳前方，边框和支架暴露在外。

## 要做的事
1. **实测显示器模型的屏幕面（必须）：** 用 `computerScreen` 的真实几何，找出屏幕玻璃面（深色材质的网格 / 面）在模型局部坐标里的**中心、法线、宽、高**（脚本读取，不要目测），算出对应的世界变换（含工位 `yaw`）。把测得的数值写进汇报与代码注释。
2. **实时屏幕平面贴合：** 平面的位置 / 朝向 / 倾角 / 宽高**取自上一步的实测值**，放在屏幕玻璃面外侧 **1–2 mm**（避免 z-fighting，沿用本项目「薄件偏移 ≥ 0.12 m 的规则」**不适用于屏幕**，屏幕用 `polygonOffset` + 1–2 mm 即可，并写明理由）；平面**略小于玻璃面**（留出边框，不盖住边框）；仍然写入同一张屏幕图集（`screenSlots`），实时屏幕内容接口不变。
3. **外观细节（一并检查，发现问题一并修）：** 显示器支架与底座是否落在桌面上（不悬空、不穿桌）；显示器正面朝向座椅方向；键盘 / 鼠标位置与桌面、显示器的相对关系是否合理（键盘在显示器正前方、鼠标在其右侧）；`screen` 的 `yaw` 随工位朝向（不要依赖默认 0）。四面 / 不同朝向的工位（北排朝南、南排朝北）逐个确认。
4. **`?layout=2` 才改；默认页面（布局一）逐数据不变。** 不新增 calls（屏幕仍走合并后的图集批次）、不新增请求；三角形增量 ≤ 0。
5. **测试：** 屏幕平面与模型屏幕面的**平行度**（法线夹角 < 1°）与**间距**（1–2 mm）、居中偏差（< 5 mm）、宽高小于玻璃面；所有工位朝向（`yaw` 0 / π）各断言一次；图集槽位数量不变；全量 `node --max-old-space-size=2048 --test --test-timeout=60000` 全过，不放宽断言。
6. **浏览器验收（必做，Playwright，高 / 低档）：** `?layout=2` 里**至少 6 个不同位置 / 朝向的工位的近景截图**（每个从斜上方与侧面各一张），确认：屏幕嵌在外壳里、边框均匀、不飘、不脱落、不穿模；有人坐着时（真实同事）的整体画面一张。控制台 0 错误，默认页面不变。
7. 备份 `office-furniture-v2.js` 与相关测试到上一级目录 `office3d-backup-o4c`；不读取或打印密钥，不重启服务。「做到 / 没做到 / 未验证」，贴实测的屏幕面中心 / 法线 / 尺寸与截图；**停下等我验收**。

**后续（rev3）：** R3-4 的家具沿用本卡的「从模型实测屏幕面」方法，工位显示器做成共用函数，不再手填常数。
