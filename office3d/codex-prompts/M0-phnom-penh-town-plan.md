## 要交付的内容（全部写进 `m0\m0-plan.md`，每节给出可复现的脚本输出）
**1. 数据体检。** 脚本 `scripts\audit.mjs`：统计各文件的要素数、字段完整率、坐标范围、异常值（空几何、重复、越界、超长 / 含控制字符的名称）；14 个 Khan 的边界是否闭合、是否有缺口（关系成员拼接成环的成功率）；道路按 `highway` 类型的总长度；地标按类型计数。**列出所有异常和你的处理决定。**
**2. 地标精选清单（≤ 30 个）。** 按明确标准（有英文名或高棉文名、类型重要、位置在 14 个 Khan 内、分布均匀）从 431 个候选里选；**必须在数据里找出并核对这些知名地标是否存在**（找不到就写「缺失」，不要编造坐标）：独立纪念碑（Independence Monument）、王宫（Royal Palace）、金边塔 / 柬埔寨塔、Wat Phnom、中央市场（Phsar Thmei）、俄罗斯市场（Phsar Toul Tom Poung）、河滨路 / Sisowath Quay 一带、永旺（AEON Mall 1 / 2 / Sen Sok）、奥林匹克体育场、国家博物馆、金边国际机场、钻石岛（Koh Pich）、Tuol Sleng 博物馆、桑园（Sen Sok）和金边火车站。每个入选地标给出：名称（净化后）、类型、经纬度、所在 Khan、选入理由。
**3. 坐标系与画布。** 选一个局部等距投影（以金边中心为原点的米制平面），给出公式、原点、地图宽高（米）、推荐的画布单位（例如 1 单位 = 10 米）、缩放级别范围；**给出办公室（智序工场）在地图上的位置建议**（推荐靠近河滨 / 独立纪念碑一带的一个虚拟位置，写明理由，**标注为虚构位置，不对应真实地址**）和它与 3D 办公室坐标系的关系（正门朝向、DR 广场出口在地图上的哪里）。
**4. 简化与体积预算。** 脚本 `scripts\simplify.mjs`：对区界、道路、水系做 Douglas-Peucker 简化（给出每层的容差和理由），输出 `derived\town-map-v0.json`（**≤ 400 KB**，含图层：`khans`、`roads`、`water`、`landmarks`，要素 id 稳定、坐标取整到 1 米）；报告简化前后的点数 / 字节数、最大几何偏差（米）。**随机抽 20 条路和 3 个 Khan 做偏差核对。**
**5. 路网与通勤可达性。** 脚本 `scripts\roadgraph.mjs`：由 `roads-major.json` 的几何（按坐标吸附端点，容差写明）建路网图，报告：连通分量数量、最大分量占总长度的比例、断点位置的前 10 处；**验证从 14 个 Khan 的每个区中心点到「办公室位置」是否存在路径**（吸附到最近道路），给出最短路径长度（米）和折算的驾驶 / 摩托 / 嘟嘟车通勤时间（速度参数写明）。**不可达的 Khan 要写原因和修补建议**（例如补连接线）。
**6. 地块网格与定价分区。** 设计「地块」（plot）：形状、尺寸（建议 20×20 米与 30×30 米两档）、由确定性算法（固定种子）在每个 Khan 内避开道路缓冲区和水系自动生成；脚本 `scripts\plots.mjs` 为每个 Khan 生成地块数并给出统计；**14 个 Khan 的价格分区表**（核心 / 内城 / 外围，写明划分依据，例如离独立纪念碑的距离，不要拿真实房价冒充）。要求：地块总数 ≥ 6,000，核心区稀缺（占比 ≤ 8%），并保证**每位同事（25 人）都有可租的开局住处**。
**7. 房产、车辆目录与价格表。** 以经济参数为锚（`baseWage = 280`，月薪档 336 / 468 / 636 / 840 / 795 / 585；房租水电共占基数 37%；个人税 12%（起征点 300）；已有储蓄行为见规划第十五节）：房型（≥ 4 种：平房、联排、公寓单元、独栋）、建造 / 装修档次、车型（摩托、嘟嘟车、小轿车、皮卡）；**价格 = 基数 × 分区倍数 ×（物价指数 0.8–1.5）**，给出完整表格和公式；**可负担性模拟（脚本 `scripts\affordability.mjs`）**：用 25 位同事真实月薪，按规划第十七节的贷款规则（首付 ≥ 20%、债务收入比 ≤ 35%、月利率 0.6%、房贷 ≤ 36 个月、车贷 ≤ 18 个月）计算每个档次**买哪档房 / 车需要多久、月供是多少、占收入比例**，并检查：**典型执行岗（T1）在 3–4 年内能买到最低档房，不能一年内买到核心区房**；价格带过松 / 过紧要调整并写出理由。持有成本（房产税 0.3% / 月、维护费、车辆折旧 2% / 月、油费 / 停车费）的数字也要给出并验证「月支出不吞掉全部收入」。
**8. 拍卖与贷款的数据合同。** 定义**数据结构（不实现）**：产权登记（plot → owner / price / mortgage / status）、贷款（本金、利率、剩余期数、抵押物、逾期记录）、拍卖（编号、标的、起拍价、限价带、出价记录、成交）；**与 T20 的追加式账本的对接方式**（账户和借贷平衡：贷款 = 金库 → 钱包的转移并记应收；还款、利息、坏账、交易税、房产税、折旧各自记在哪个科目；**守恒不变量怎么扩展**：`Σ钱包 + 金库 = 累计发行 − 累计永久回收` 在有应收贷款时如何保持成立）；**幂等键**和**不可变性**（产权变更只能追加）；确定性竞拍的算法草案（估值函数、出价序列、平局规则，同一拍卖编号重放结果恒定）。
**9. `/town` 页面架构（不实现）。** 技术方案（原生 canvas 2D，**无新依赖**）、图层与绘制顺序、缩放 / 拖动 / 点选交互、性能预算（总资源 ≤ 2 MB；在集成显卡上 ≥ 30 FPS 的做法）、与办公室页面的跳转、**界面署名位置**、**所有来自数据的文字转义**、局域网 / 大屏令牌的访问边界（沿用 `server.mjs` 的访问控制思路，写出建议但不改代码）；服务端接口合同（例如 `GET /town/map`、`GET /town/state`）及字段；通勤动画的数据来源（**只来自真实的上下班记录**，说明用哪份记录、没有记录时显示什么）。
**10. M1–M4 实施拆分。** 把后续实施拆成 **6–10 个互不冲突的小任务**（每个写：目标、允许改 / 不得改的文件、依赖、验收要点、预计体积 / 性能影响、适合的执行者类型），标出可并行和必须串行的关系；**`app.js` 不得被这些任务修改**（`/town` 是独立页面）。
**11. 风险与未决项。** 你发现但不能自己决定的事（OSM 数据质量、名称语言、道路连通性缺口、署名与许可的界面落地、地块数量与价格带的取舍、贷款 / 拍卖对经济循环的压力），每条给推荐选项。
