# T17-agent-chat：点击同事可对话；对话可转成任务，任务一律交给 Lead 分解并派发

先读 `_common.md`。**本任务的例外规则：** 允许新增 `chat.mjs`、`chat-panel.js`、`tests/chat.test.mjs`、`tests/chat-panel.test.mjs`、`chat.json`（总开关 + 额度 + 状态）、目录 `chats/`（对话记录）；允许修改 `server.mjs`（**只限第 6 节接线**，不要碰局域网访问码、`hostOk`、大屏令牌、`act()` 已有分支、静态文件白名单）、`ui.js` 与 `app.js` 与 `index.html`（**只限**「点击同事 → 💬 对话」入口、对话面板、必要样式；`app.js` 只留几行挂钩）、`blocked.mjs` / `acceptance.mjs` / `standup.mjs` / `memory.mjs`（**只限**各加一处「标题以 `CHAT_SESSION_PREFIX` 开头的会话任务不处理」的过滤，每处不超过 6 行并各写测试）、`README.md`。**不要改** committee / wall / rework 等其它模块，**不要改任何 agent 的 AGENTS.md**（Claude 另行配置 Lead 与同事的对话规则）。**验证时不得向 Paperclip 发任何写请求**（POST / PATCH / PUT / DELETE）：全部写逻辑只用模拟接口测试；第一次真实运行由 Claude 在验收后做。不新增依赖。备份到 `office3d-backup-agent-chat`（办公室目录没有 Git）。**不要与改 `app.js` / `ui.js` / `server.mjs` 的其他 Codex 任务同时进行。**

## 董事会已定的规则
1. 点击每位同事都可以与他对话；对话可以生成任务；**生成的任务一律先交给 Lead，由 Lead 补契约、分解并派发**（不管你在跟谁聊）。
2. **额度**：每位同事每小时最多 **6 轮**，全公司每天最多 **60 轮**（「一轮」= 你发一条消息；超了提示「额度用完，下一个小时 / 明天再聊」，不发出去）。
3. **下班**：同事暂停（下班）时**也可以发消息**，界面写明「下班了，明天 8:30 后回复」，消息**排队**，上班后按间隔依次发出。
4. **派发**：Lead 直接分解派发，**不走委员会投票**；只受「每天限额」和「资金类走董事会审批」约束（这两条由 Lead 的规则和现有机制保证，本任务只负责把任务建好交给 Lead 并带上必要标记）。
5. 你的原话**写进任务描述**，但必须先过密钥 / 服务器地址 / 账务数据扫描，命中则拒绝发送并提示类别（不回显命中的内容）。

【背景】Paperclip 里没有现成的聊天功能（任务上的 `conversation*` 字段全部为空，不要依赖）。同事只在被唤醒后运行一次才回复：**评论会唤醒负责人**，所以「对话」= 给同事名下的一张会话任务发评论、等他回评论。每次回复都耗额度、要几十秒；同事暂停时不会运行。

## 1. 会话任务（每位同事每个金边日一张）
- 标题 `【对话会话】<岗位名> · YYYY-MM-DD`（前缀常量 `CHAT_SESSION_PREFIX = '【对话会话】'`，从 `chat.mjs` 导出），项目「运营与知识库」，负责人 = 该同事，状态 `todo`，优先级 low。第一条消息发出时才创建（没人聊就不建）。**程序只管理标题以该前缀开头、且由本程序创建（`chat.json` 里有登记的 id）的会话任务**，绝不修改其它任务。
- 描述（≤ 1200 字，遵守 4000 字上限）：说明「这是董事会与你的对话」；规则：① 用评论回复，≤ 300 字，口语化；② **不要**创建任务、不要改任何任务状态、不要执行操作；③ 对话里出现可以做的事，在回复**最后单独一行**写 `建议任务：<一句话标题> | <一句话说明>`（可选，最多 1 条）；④ 不得在回复里写密钥、令牌、服务器地址、账务数据；⑤ 你不确定或超出你岗位的，直接说并建议找谁。
- 每个金边日结束后（第一次发现已下班且没有待回复消息）把当天会话任务改 `done`；次日新消息建新会话任务。**状态改动只针对上面登记的会话任务。**

## 2. 发送、排队与回复
- 动作 `chat_send {agentId, text}`（`act()` 新增，局域网只读设备 403，沿用现有令牌机制）：校验 → 扫描 → 额度 → 入库 → 发送或排队。
- **校验**：`text` 去首尾空白后 1–600 字；同事存在且不是 `terminated`；**同一位同事同时只能有 1 条待回复消息**（还没收到回复或超时前不能再发，界面提示「等 TA 回复后再说」）。
- **扫描**：复用 `memory.mjs` 导出的 `scanMemoryText`（`import` 即可，**不要复制规则、不要改 `memory.mjs` 的扫描**）；命中即拒绝，错误里只给类别（密钥 / 服务器地址 / 账务数据），**不回显原文**，也不写进 `chats/`。
- **额度**：按金边时间统计，持久化在 `chat.json`；超限返回 429 和可读文案。**排队中的消息在入队时就计入额度**，防止下班时刷屏。
- **发送时机**：同事状态不是 `paused` 且 `dutyOn()` 为真 → 立即把原话作为评论（首行 `【对话】`，正文为原话）发到会话任务。否则**只在本地排队**（不发给 Paperclip），上班后（同事恢复且 `dutyOn`）由程序**每 15 秒一条**依次发出（防止同时唤醒一批）。重启后队列保留。
- **回复识别**：发送后每 5 秒只读 `GET` 会话任务评论，取**该条消息之后第一条 agent 评论**作为回复；程序自己的评论不算；10 分钟没有回复则标记 `timeout` 并提示「TA 暂时没有回复」，**不重发**。回复入库前走 `wall.mjs` 的 `redactText`（金额 / IP / 邮箱 / 链接 / 疑似密钥打码，复用，不要另写）；长度截到 1500 字。
- **记录**：`chats/<岗位名>.jsonl`，每行 `{id, at, role:'user'|'agent', text, status}`，原子追加，保留 30 天（启动时和每天清理）；损坏行跳过并计数。**对话内容不得进入事件账本（`events-ledger`）、回放、协作关系图、`/state` 的任何字段（`/state` 只给额度计数和各同事的待回复标记，不含正文）、大屏。**

## 3. 对话转任务（确认后才创建）
- 两个入口：① 同事回复里有 `建议任务：…` 行时，面板显示卡片「建议任务：<标题>」+ 「转成任务」按钮；② 对话窗口顶部固定「把这段对话转成任务」，你填标题（必填，≤ 80 字）和补充说明（选填，≤ 300 字）。**绝不自动创建**——必须点确认。
- 动作 `chat_to_task {chatAgentId, title, note, messageIds[]}`：创建一张 Paperclip 任务：标题 `【对话任务】<title>`，**负责人固定为 Lead**，状态 `todo`，优先级 medium，项目沿用「运营与知识库」；描述（≤ 3500 字）包含：来源（与谁、金边时间、会话任务编号）、选中消息的原话（已扫描 / 脱敏，≤ 800 字）、对话里提到的**建议负责人**（如果就是被对话的同事，写 `建议负责人：<岗位名>（仅供参考，由 Lead 决定）`）、一个**待 Lead 补全的契约骨架**（目标 / 范围（允许改 / 禁止碰）/ 前置条件 / 验收项 AC-x 与证明方式 / 交付物 / 责任 / 停止条件，沿用知识库 `流程/模板/任务契约.md` 的标题，内容留空并写「待 Lead 补全」）。
- **资金类标记**：用 `standup.mjs` 导出的 `MONEY_RE`（复用，不要复制）检查标题 + 原话；命中则描述顶部加一行 `类别：资金类（账务 / 提现 / 鉴权 / IAM / 迁移 / 密钥 / 入账队列）→ 只允许 GoSenior / DBEngineer 实现，必须先由董事会审批`。程序**不替 Lead 做派发和审批**。
- **限额**：对话产生的任务每个金边日最多 **5 个**；超了拒绝并提示。每条对话消息最多被转一次（`chat.json` 记录已转的消息 id，防止重复建任务）。
- 创建后回显任务编号，面板里可点击跳转（沿用 `openIssue`）；记录到 `chat.json` 的 `tasks` 里（任务 id、编号、时间、来源会话）。

## 4. 与现有程序的隔离（每处 ≤ 6 行，各写测试）
会话任务（标题以 `CHAT_SESSION_PREFIX` 开头）**不得被这些程序当成普通任务处理**：`blocked.mjs`（阻塞巡检跳过）、`acceptance.mjs`（超时验收跳过）、`standup.mjs`（晨会提案校验丢弃并写明「对话会话任务」）、`memory.mjs`（记忆库注入跳过，沿用现有 `memorySkip` 的方式）。读不到标题时按普通任务处理，不能因此卡死这些程序。`【对话任务】`（转出的任务）是普通任务，照常被处理。

## 5. 界面（`chat-panel.js` + 最小挂钩）
- 点击人物后的详情卡加按钮「💬 对话」（局域网只读 / 大屏模式 / 同事 `terminated` 时隐藏或置灰并说明原因）。
- 对话面板（抽屉或弹窗，沿用现有弹窗写法，窄屏可用）：消息列表（你 / 对方，时间、状态：排队中 / 已发送 / 思考中 / 已回复 / 超时）；输入框（≤600 字，计数）、发送按钮（Enter 发送，Shift+Enter 换行）；顶部状态行：同事当前状态（空闲 / 运行中 / 下班了，明天 8:30 后回复）、额度「本小时 n/6 · 今日 n/60」；固定提示「同事的回复由 AI 生成，仅供参考，不代表已执行；对话不会改动任何任务」。
- 「转成任务」入口按第 3 节；建好后在消息流里插入一条系统提示「已建任务 CMP-xxx，交给 Lead」。
- 回复到达时，该同事头顶显示一个本地小气泡「💬」（**纯前端、不写事件账本**），打开面板后消失。
- 所有来自数据的文字用 `esc()`；不得请求 `/chat*` 以外的新接口；`prefers-reduced-motion` 下无动画。

## 6. 接线（`server.mjs`，只允许这些）
1. `import { createChat } from './chat.mjs'`，仿照 `createBlockedPatrol` 创建；传入 `get`、`send`、`notify`、`dutyOn`、`now`、`agents`（名单和状态）、`redactText`（来自 `wall.mjs`）。**重启后第一次发送 / 回复轮询等 1 分钟**，之后正常。
2. 只读 `GET /chat?agent=<岗位名>`：返回该同事的消息、额度、待回复、排队、建议任务；`GET /chat/summary`：额度与各同事待回复标记（不含正文）。放在现有访问控制之后。**对话内容只有本机可看**：局域网设备和大屏令牌设备访问这两个接口一律 403（沿用 `API_PATHS`；`/state` 里的 `chat` 摘要不含正文，局域网可见）。
3. `/state` 里加 `chat: chat.summary()`（额度计数、各同事是否有待回复 / 未读标记、`enabled`；**不含正文**）。
4. `act()` 里**只新增**：`chat_send`、`chat_to_task`；并把 `chat_` 加进已有的「结果透传」前缀判断。
5. `chat.json` 的 `enabled:false` 为总开关，**默认关闭**（文件不存在按关闭处理）；关闭后面板只显示「对话功能未开启」，不发任何评论、不建任何任务、不轮询。
6. 状态保存在 `chat.json`（额度计数、会话任务登记、队列、已转消息、任务记录），原子写入，损坏时视为关闭并在 `/state` 提示，不崩溃。
