# T13-rework-cap：有边界的返工（第 5 条）——识别返工轮次，超限转人工，并挡住自动流程

先读 `_common.md`。**本任务的例外规则：** 允许新增 `rework.mjs`、`tests/rework.test.mjs`；允许修改 `server.mjs`（**只限第 5 节接线**，不要碰局域网访问码、`hostOk`、大屏令牌、`act()` 已有分支、静态文件白名单）、`governance.mjs`（**只限**加一个「返工」分区的数据，不改现有输出）、`ui.js`（**只限**治理中心里加一节「返工」，和待验收卡片上加一个徽标）、`acceptance.mjs` 与 `standup.mjs`（**只限**各加一处「返工超限的任务不得进入」的过滤，见第 4 节，每处改动不超过 10 行，并写测试）、`README.md`。**不要改** committee / blocked / memory / wall / workload 等其它模块。**不得向 Paperclip 发任何会改变任务状态、负责人、依赖的请求**；唯一允许的写入是第 3 节规定的带标记评论。不新增依赖。备份到 `office3d-backup-rework`（办公室目录没有 Git）。**不要与其他 Codex 任务同时进行**（共用 `server.mjs` / `ui.js`）。**知识库模板和同事的 AGENTS.md 由 Claude 另行维护，你不要改。**

【背景】知识库《任务管理流程》第 6 节规定：返工留在原任务里，问题编号 R1、R2 在整个任务里不变，**同一任务退回到第 3 轮就停下，升级给 Lead 和董事会**。现在这条只是规则，没有程序识别，靠同事自觉。模板格式（`流程/模板/返工记录.md`）：评审员「【第 N 轮退回】」后接若干 `R<n> ｜ 对应 AC-x ｜ 问题：… ｜ 复现 / 证据：…`；执行者「【第 N 轮修复】对象版本：…」后接 `R<n> ｜ 修复：… ｜ 复验：… ｜ 状态：已修 / 未修（原因）`；评审员「【第 N 轮复验】R1 通过 / 未通过 ｜ …」。先读 `E:\VirtualAIOffice\knowledge\流程\任务管理流程.md` 第 6 节和上述模板。

## 1. 识别（`rework.mjs` 纯函数，输入任务评论数组，输出每个任务的返工状态）
- 解析三类评论（标题行容忍全角 / 半角括号、「第 2 轮」「第二轮」、前后空白）：退回、修复、复验，抽出轮次 N、各 `R<n>` 条目及其状态。**无法解析的格式不猜测**，记为「格式不全」并给出原因。
- 每个任务输出：`rounds`（已退回的最大轮次）、每个 R 项的状态（`open` 未修 / `fixed` 已修待复验 / `verified` 复验通过 / `failed` 复验未通过）、`openItems`、`repeatedItems`（同一 R 项在 ≥2 个轮次的复验里都未通过）、`formatIssues`（退回缺「对应 AC」或「复现」、R 编号重排 / 复用）、`capped`（`rounds ≥ 3` 且任务尚未结束）。
- 只看 **agent 评审员和董事会写的退回**（评论作者必须是 agent 或董事会）；程序自己的评论（标记 `【返工巡检】`）不参与计数。

## 2. 阈值与口径（`rework.json`，默认值如下，可调；页面显示用了哪些阈值）
`capRound: 3`（达到第 3 轮即为超限）、`warnRound: 2`（第 2 轮提示「再退一轮将超限」）、`repeatItemRounds: 2`。资金类任务（`standup.mjs` 的 `MONEY_RE` 口径，复用不要复制）同样识别和显示，但**不自动发评论**，只通知董事会。

## 3. 动作（全部默认关闭，`rework.json` 的 `enabled:false` 为总开关；文件不存在按关闭处理）
- **超限**（`capped`）：对该任务**只做一次**：① 在任务里发一条评论，首行 `【返工巡检】`，内容：已退回到第 N 轮、未关闭的 R 项清单（编号 + 一句话，不贴证据原文）、「按流程请 Lead 与董事会决定：继续 / 拆分 / 换人 / 取消；在决定前请不要再自行提交验收」；② Telegram 通知董事会一次（任务编号 + 轮次 + 未关闭 R 项数，沿用现有 `notify`）。同一任务以后不再重复发。
- **预警**（第 2 轮）和 **同项重复未通过**：只在治理中心显示，不发评论、不通知。
- **格式不全**：只在治理中心显示。
- 所有评论遵循流程第 7 节的中文简短写法；每轮扫描最多处理 6 个任务；同一任务 24 小时内最多一条巡检评论；**评论会唤醒负责人**，所以只在超限这一种情况发（汇报里评估多余运行风险）。
- **不改状态、不改负责人、不取消、不拆分、不替任何人做决定。**

## 4. 挡住自动流程（只加过滤，不改其他逻辑）
- `acceptance.mjs`（超时验收）：`capped` 的任务**不进入委员会批次**，结果等同「交董事会」，在批次记录里写明原因「返工超限」。
- `standup.mjs`（晨会派单）：`capped` 的任务**不得作为候选或被派发**（Lead 提案里出现的，校验阶段丢弃并写明原因）。
- 两处都通过 `rework.mjs` 导出的纯函数判断；读不到返工状态时（接口失败）**按未超限处理并记日志**，不能因此卡死晨会或验收。

## 5. 接线（`server.mjs`，只允许这些）
1. `import { createRework } from './rework.mjs'`，仿照 `createBlockedPatrol` 创建；传入 `get`、`send`（评论）、`notify`、`dutyOn`、`now`、`isMoney`。**重启后第一次扫描等 5 分钟**；每 30 分钟扫一次状态为 `in_progress` / `in_review` / `todo` / `blocked` 且评论里出现过「退回」的任务（评论按任务更新时间缓存，只读 GET）。
2. 新增只读 `GET /rework`：返回所有有返工记录的任务的状态（编号、标题、轮次、各 R 项状态、阈值、是否已发过巡检评论）；放在现有访问控制之后，**大屏令牌设备 403**（沿用 `API_PATHS`）。
3. `/state` 里加 `rework: r.view()`（摘要：超限数、预警数、最近 10 条处理记录；不含评论正文）。
4. `act()` 里**只新增**一行 `rework_run`（董事会手动扫描一次；局域网只读时沿用现有 403），并把 `rework_` 加进已有的「结果透传」前缀判断。
5. 状态保存在 `rework.json`（已处理任务、时间），原子写入，损坏时视为关闭并在 `/state` 提示，不崩溃。

## 6. 界面（`ui.js`）
- 治理中心加「返工」一节：超限任务置顶（红）、预警（黄）、格式不全 / 同项重复（灰）；每行显示轮次、未关闭 R 项数、是否已通知、停留时间；点击任务编号沿用现有跳转。所有文字 `esc()`，窄屏可用，局域网只读时「立即扫描」置灰。
