## 做到

- 背景树冠仍为 162 个三维叶簇，高档每簇 128 片、低档 32 片，原位置、方向、颜色和可见包络保持。每片椭圆由两个三角形改为一个覆盖原可见范围的大三角形，仍按相同 UV 椭圆裁边。包围盒/球取实际可见四角，不把裁掉的外侧顶点算成冠幅。
- 原环境球冠此前缩到不可见仍提交绘制。现在只在私有替代树冠可见、源矩阵归本模块所有且对应回调仍有效时临时提交 0 实例，结束即恢复；不改共享几何、材质或风写入器。模块隐藏/销毁恢复原回调，渲染中断也恢复本模块临时 count，其他调用方主动改动的 count 保留。
- 爱心榕树仍为 1000 / 500 组小叶，树干、分枝、树池、颜色、实例矩阵及可见冠幅不变；仅 ALIGN 样板使用新叶面提交。稳定 V3 的原几何/材质快照仍精确匹配。
- 五个真实盆栽的正反重复面改为双面材质，保留原 GLB 缓存包络和原碰撞代理。中央八盆植物复用已有轮廓叶面；低档花境只重排轮廓索引，叶片数量、全部原顶点/法线、颜色、位置、两面和原单批次保留。细小内部曲面分段属于低档精度变化，未伪称所有像素不变。
- 新增私有 `office-vis2/leaf-pass.js`：在已有 GTAO 法线阶段仍执行自有叶片裁边，输出相机空间法线；普通阶段保持原 PBR 色彩。不改全局覆盖材质、Three.js、曝光、灯光或渲染器，不新增独立帧循环。低档原管线不执行 GTAO。

生产代码为 `office-heart-banyan.js`、`office-vis2/plants.js`、`office-vis2/bar.js` 与上述新辅助模块；更新规范 LF 资产清单、两个实现相关的精确三角形期望，新增五项测试。不改 app/ui/index、共享加载器、仓配或任何业务入口。没有新贴图或外部素材下载；新增一个静态 JS 模块，不新增业务轮询/写请求或 AI 调用。
